# 评审彩排 · PDM.Review-Rehearsal（技能链评审前哨环·V1.0）

链条：… → #4 修订原型 PDM.Refinement-Prototype → **#5 评审彩排 PDM.Review-Rehearsal（本技能）** → 下一轮业务沟通（第2~N次业务沟通，即真实业务评审所在环）。窗口＝每次原型修订＋PRD 同步完成后 → 下一次业务沟通前。定位＝上真实评审场之前的**模拟业务评审**：替业务评审方先把问题问出来，别等问题留到评审现场才爆。命名规则（0929 拍板沿用）：目录与 name 统一点分 PDM.Review-Rehearsal，中文短名「评审彩排」写入 name 括号与触发词。

## 模型路由

> 落点表与验证纪律见 PDM.Model-Routing（单一事实源）；此处只写本技能分配，模型换代只改该文件。

- **主验＝异族审**（Kimi-K3，走积分通道；备选第二异族 MiniMax-M3）——跨厂商视角即彩排价值：写方案的 GLM 系自评有同源盲区。
- **异族纪律**：独立会话跑完，禁会话中途切入（K3 官方声明对历史思考内容敏感）；任务书硬边界＝本技能既有纪律「只提问不改稿」直接充当（吸收其「过于主动」局限）；API 直连输出单价高，重输出走积分。
- 出口仍为人判；模型只负责出题。

## 输入（两件缺一不开工）

1. **当前版方案**——主业务流程图.html（PDM.Preparation-Prototype S4 首绘、PDM.Refinement-Prototype 持续修订的那张"方案"）＋同版页面原型（以原型根 README-修订记录.md 的当前版本行为准）。
2. **背景资料**——功能对照表、口径台账（NOTE-CHECK／决策台账）。**仅作背景校准理解，不直接入题**（见 C2 口径）。

任一缺失：停下告知用户缺什么，不降级开工。

**例外出口（v1.0.1，仅主业务流程图单项）**：流程图缺位且用户**明示豁免**时，按「页面原型为纲」降级出题，并在《彩排问题清单》头部声明口径：「本轮以页面原型为纲（流程图豁免；非初绘入口项目——源码复刻/存量改造起步属合法入口）」。豁免仅适用于流程图：页面原型缺位仍不开工。缺位与豁免应由 PDM.Refinement-Prototype R1 输入校验当场提出，本出口是承接而非替代。

## 流程（4 步）

### C1 立视角（先站到评审席上）
以**业务评审方视角**（客户业务侧评审人：关心业务跑不跑得通、口径前后一不一致、有没有拍板过的事没落实）通读主业务流程图，只看主流程。

### C2 出题（主流程为纲＋页面佐证）
**提问口径（2026-10-11 拍板）**：
- **以主业务流程图.html 为纲提问**——沿主流程节点顺序逐节点出题（这个环节谁负责？两步之间凭什么衔接？异常走哪？）；流程图豁免轮次改以页面原型为纲（见输入例外出口，清单头部已声明）；
- **页面原型作佐证**——流程题下到页面里核对落实；**页面与流程矛盾处（流程有页面没有、页面有流程没画、两者说法不一）也入题**；
- 每问**标注出处**：主业务流程图节点名或页面名，无出处不入清单；
- 功能对照表／口径台账仅作背景资料不直接入题（背景里已拍板"不要"的不再问，背景里明确待定的可追问）。

产出《彩排问题清单》（文档，头部版本注释行记版本，规则见 VERSIONING.md §8）。

### C3 交人判定（出口＝人判）
《彩排问题清单》交**人判定**。**出口不设分级、不做出口判定，一律由人判定**——"问题清零或可控"由人拍板；技能只负责提问与循环驱动，不替人下结论。

### C4 驱动循环（未过即修，修完再问）
人判未过 → 驱动 PDM.Refinement-Prototype 按清单修订（修订落盘由其承担：原型根 README-修订记录.md 记版本，**触发来源＝彩排问题清单**；修订后其 R6 必经步会同步使用 PDM.PRD-Generator 增量更新）→ 修订完成后再次彩排提问 → 循环，直至人判通过、放行下一轮业务沟通（第2~N次业务沟通）。

## 纪律

- **只提问不改稿**：本技能不代改原型／流程图，修订一律由 PDM.Refinement-Prototype 承担。
- **题题有出处**：出处只认主业务流程图节点名或页面名。
- **背景不入题**：对照表／台账不直接生成问题。
- **每轮新清单**：每轮重新出题，上一轮已解决项不再重复入题（除非修订引入回归）。
- **不臆造评审标准**：只从方案本身（流程＋页面）出题，不虚构行业规范类要求。

- 《彩排问题清单》＝文档：头部版本注释行（md 引用块），每轮落盘按 VERSIONING.md §8 语义递增。
- 原型侧版本：由 PDM.Refinement-Prototype 在 README-修订记录.md 记录（当前版本行＋变更履历表［版本/日期/变更摘要/触发来源］），触发来源写「彩排问题清单 V{x.y.z}」。

# 技能版本号规则（PDM 技能族）

适用范围：PDM.* 全部技能。本文件随每个技能目录携带、随发布包自足传播；
族内各副本内容必须一致，修改本文件须同步到所有技能目录。

## 1. 格式

- 一律三段 `MAJOR.MINOR.PATCH`，frontmatter 中写裸值、不带引号、**族内一律无后缀**：
  - ✅ `version: 1.2.0`、`version: 3.6.0`
  - ❌ `version: "1.2"`（两段＋引号）、`version: 1.0`（两段）、`version: "1.1.3"`（带引号）、`version: 3.6.0-pdm.2`（带 fork 后缀）
- fork 自外部上游的技能同样用裸三段号；上游锚点与本地适配史记录在该技能的溯源文件（如 `溯源与同步.md`），不进版本号。上游升级重基于时按第 2 节语义正常递增（通常 MINOR）。

## 2. 三段语义（技能＝方法论文档，不照抄软件 semver）

- **MAJOR**：流程骨架或输入输出契约变更——步骤结构、触发条件、产物
  要求改变，导致按旧版编写的下游任务书（goal 提示词等）预期失效。
- **MINOR**：向后兼容的新增——新章节、新规则、新参考文件，旧用法仍成立。
- **PATCH**：不改变行为预期的修正——错字、示例更新、格式统一、链接修复。

## 3. 版本权威与正文标记

- frontmatter `version:` 是唯一版本权威；正文标题里的 V 标记（如
  「V1.1」）仅是历史注释，两者不一致时以 frontmatter 为准。
- 新变更不再要求维护正文 V 标记，只改 frontmatter。

## 4. 评审状态不进版本号

- 版本号只描述内容状态；批准与否由位置表达：
  `skill-iterate/proposals/`（暂存区）＝待评审，`skills/` 正本＝转正，
  转正不改号。
- rc 字样只可出现在暂存文件名中；正本 frontmatter 永远是干净三段，
  禁止任何后缀（❌ `3.6.0-rc1`、❌ `3.6.0-pdm.2`）。

## 5. 递增时机

- 谁改谁递增，在落盘转正的同一轮内更新 frontmatter；
  工作与记版本是两个动作，后者不许拖到下一轮。

## 6. 正本、同步与发布包

- 项目 `skills/` 目录是唯一正本；agent 安装目录（`.zcode/skills`、
  `.claude/skills` 等）是副本，同步后两侧 `version:` 必须一致。
- 发布包按日期快照命名（如 20261010），与技能版本解耦；每次打包
  必须随包生成 manifest（技能名＋版本清单）。

## 7. 同步校验（Git Bash）

```bash
for d in "<正本skills路径>"/*/ ; do
  n=$(basename "$d")
  a=$(grep -m1 '^version:' "$d/SKILL.md" 2>/dev/null)
  b=$(grep -m1 '^version:' "<agent安装路径>/$n/SKILL.md" 2>/dev/null)
  [ "$a" = "$b" ] || echo "不一致: $n  正本[$a]  安装[$b]"
done; echo 校验完成
```

## 8. 交付物版本（技能产出物的版本规则）

适用范围：技能产出的交付物（原型、PRD、主业务流程图、问题清单、
功能对照表等）。与第 1~2 节的「技能版本」相互独立、互不联动。

1. **格式**：V＋三段，如 `V1.2.0`。
2. **语义**：MAJOR＝方案性变更（页面/章节增删、业务流程改变）；
   MINOR＝兼容新增（新页面/字段/列，已有内容不动）；
   PATCH＝修正（错字/样式/口径，不改含义）。
3. **记录位置**：文档＝头部版本注释行——md 用引用块、html 用
   `<!-- V1.2.0｜日期｜变更摘要 -->`、docx 用封面/页脚版本行；
   原型＝文件夹根 README-修订记录.md。
4. **递增时机**：每次评审驱动的修订落盘时同轮递增。
5. **状态与版本分开**：业务评审版/待评审等状态不拼进版本串。
6. **过程快照**：过程快照文件夹（vN-会M）保留为轮次归档，
   版本号只管轮内演进。
7. **PRD 联动**：PRD 与原型各自独立编号、不绑定跳号；
   每次联动更新在 PRD 头部版本注释记联动来源
   （如「随原型 V1.3.0 同步」）。

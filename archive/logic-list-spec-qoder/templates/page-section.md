# 页面章节模板 V1.0

单个页面在业务逻辑清单中的标准三表结构。

---

## 模板结构

```
### {X}.{Y} {页面名称}（{filename}.html）

![{页面名称}](./screenshots/{filename}.png)


#### {X}.{Y}.1 功能用例表

（场景/操作/预期结果 三列表格）

#### {X}.{Y}.2 关键字段数据来源

（字段/数据来源 两列表格）

#### {X}.{Y}.3 业务逻辑增强

（问题/确认结果 两列表格，可选）
```

---

## 1. 功能用例表（必选）

```markdown
#### {X}.{Y}.1 功能用例表

| # | 场景 | 操作 | 预期结果 |
|---|------|------|----------|
| 1 | 图片轮播 | 左右滑动主图 | 切换图片，图片指示器更新如"1/3"更新为"2/3" |
| 2 | 选择规格 | 点击规格属性值选项 | 选中项高亮，对应商品主图变更 |
| 3 | 提交订单 | 点击"立即支付" | 跳转支付页（`payment.html`） |
```

### 编写规则

- **#**：页内从 1 递增，不跳号
- **场景**：2-6字名词短语
- **操作**：动词开头，包含元素名称或按钮文案
- **预期结果**：具体到文案、颜色值（附十六进制）、动画名、跳转页面文件名
- 每条用例必须能在源码中找到对应实现

### 典型用例类型

| 用例类型 | 识别方式 | 示例 |
|----------|----------|------|
| 点击操作 | `addEventListener('click')` | 点击"加入购物车" → 提示"已加入购物车" |
| 输入校验 | `if (!value)` 或 maxlength | 未输入内容→提交 → 提示"请输入评价内容" |
| Tab/筛选切换 | `.tab-*` / `.filter-*` | 点击Tab → 列表过滤，选中项底部下划线 |
| 状态切换 | `classList.toggle` | 点击开关 → 滑块动画，开启=橙色+右移 |
| 弹窗操作 | overlay + popup 结构 | 点击蒙层 → 弹窗关闭 |
| 页面跳转 | `location.href` / `<a href>` | 点击按钮 → 跳转目标页（`xxx.html`） |
| 空状态 | `if (data.length === 0)` | 列表为空 → 图标+"暂无数据"文案 |
| 视觉反馈 | CSS `.active` / `@keyframes` | 选中项渐变橙色背景白字 |

## 2. 关键字段数据来源（必选）

```markdown
#### {X}.{Y}.2 关键字段数据来源

| 字段 | 数据来源 |
|------|----------|
| 商品信息（图片/名称/规格/价格） | 品牌商城后台商品管理 — 通过SKU ID关联 |
| 商品上下架状态 | 品牌商城后台商品管理 — 实时查询 |
| 购物车商品数量 | 用户操作 — 本地/后端购物车数据 |
| 总价/总数量 | 前端实时计算 — 基于勾选商品 |
| 优惠券信息（满减规则） | 品牌商城后台优惠券菜单（建议：品牌商城后台运营配置 — 当前商品参与的优惠券和满减活动） |
```

### 编写规则

- **字段列**：字段名称 + 括号列举子字段（如 `商品信息（图片/名称/规格/价格）`）
- **数据来源列**：格式为 `来源系统 — 具体说明`
- 每个页面可见的独立信息单元都应有一行

### 确定的数据来源

直接填写，不需要建议前缀：

```
品牌商城后台商品管理 — SKU主图+SKU轮播图
前端实时计算 — 基于勾选商品
用户操作 — 本地/后端购物车数据
上一页面传入 — 待评价订单商品
```

### 不确定的数据来源

留白并附建议答案，使用 `（建议：...）` 格式：

```
品牌商城后台{具体模块}（建议：品牌商城后台商品管理 — SKU规格属性）
```

**判断标准**：
- 源码中写死的配置数据 → 来源为"前端固定配置"
- 从 localStorage 读取 → 来源为"用户操作"或"本地缓存"
- 涉及后端计算或外部系统 → 需要确认具体来源模块

## 3. 业务逻辑增强（可选）

```markdown
#### {X}.{Y}.3 业务逻辑增强

| # | 问题 | 确认结果 |
|---|------|----------|
| 1 | 库存不足时前端提示策略？ | 库存漏斗策略：<br>- 加购时（宽松）：...<br>- 下单时（严格）：...<br>- 支付时（兜底）：... |
| 2 | 用户多设备同时操作购物车的合并策略？ | （建议：同SKU数量相加，异款直接追加，数量冲突以最后修改时间为准） |
```

### 何时生成

仅在以下情况生成此表：
- 存在跨页面的状态同步问题（如库存、购物车合并）
- 涉及时间窗口限制（如自动取消、评价期限）
- 涉及并发/防重策略（如重复提交、支付幂等）
- 涉及数据一致性（如积分返还、库存回滚）
- 涉及业务规则选择（如排序策略、分页条数）

### 确认的答案

业务方已确认的答案直接填写，可使用 `<br>` 分行列举：

```
30天（超时未评价一般系统默认好评或关闭评价入口）。
```

### 不确定的问题

确认结果列留空并附建议，使用 `（建议：...）` 格式：

```
（建议：10条每页，时间降序排列）
```

## 截图引用

位于 H3 标题和第一个 H4 之间：

```markdown
![{页面名称}](./screenshots/{filename}.png)
```

- 使用**相对路径**（从文档目录指向 `./screenshots/`）
- 文件名与页面 HTML 文件名一致（`.html` → `.png`）
- 截图通过 Chrome CDP 自动生成（375×812 视口，2x 缩放，注入登录态）

# PDM.NOTE-CHECK · 会议记录事实核查 v1.1.1

> 定位：PDM 链路的**会议记录前置质检层**——在任何分析技能消费会议记录之前，先把"记录里说的"与"事实／行业惯例／本项目前序口径"对齐，并交付可直接消费的净化修订版。
> 方法细则：`references/notcheck-method.md`（独立成文，零外部依赖）。
> 驱动案例：汽车物流包装租赁软件 4 次需求沟通会核查（2026-10-08）——"零部件"一词两义耗掉 3 次原型迭代、"路凯"7 种转写写法、应收应付口径跨会冲突，全部转化为本技能机制（错误模式库见 method §十一）。

---

## 一、定位与适用场景

回答一个核心问题：**"这份会议记录，能信多少？哪里要改？改完才能给下游用。"**

适用：
* 需求调研会／售前拜访／供应商谈判／内部评审——任何要喂给 AI 分析的会议逐字稿或纪要（不限场景）
* 同一项目多场会议的**反复交叉核对**：口径漂移检测、需求矛盾确认、术语统一
* 下游分析前置净化：给 PDM.AI-DIG / PDM.Preparation-Analysis 输入前的事实层把关

不做：
* 需求质量分析（模糊词/六要素/真伪需求 → PDM.Preparation-Analysis 内置 REQ-CHECK；分工=本技能核**事实层**，先事实后质量）
* AI 节点挖掘（→ PDM.AI-DIG）
* 替代用户改写决策：内容层订正必须经用户确认（两段式）

## 模型路由

> 落点表与验证纪律见 PDM.Model-Routing（单一事实源）；此处只写本技能分配，模型换代只改该文件。

- **写·分层**：①预处理与名称归一等机械步＝验 flash·批量档·非思考（闲时半价，目录批跑默认排夜间）；②事实单元抽取＝批量档·思考开＋分窗【例外位·召回敏感】；③④⑤交叉核对与矛盾四分类＝写旗舰·中思考。
- **验**：套餐 flash——红旗条目反向抽查，一次性子代理只回问题清单（每条带证据锚点，≤30 条），禁止重写交付物。
- 通道不支持子代理指定模型时：降为主会话独立段落执行，产出标注「同模型验证（未异厂）」。

## 二、输入约定

| 参数 | 必需 | 说明 |
|------|------|------|
| 会议记录 | ✅ | 逐字稿（优先，全信号）/ 纪要（降档）。md/docx/pdf/html/txt；扫描版 pdf 先走 vinfield-PDF OCR 纪律（临时文件走系统 TEMP 目录）。**批量形态**：给项目文件夹路径即触发（扫描全部会议记录→按文件名日期排序→逐件核查，见 §三批量执行） |
| 知识库 | 可选 | **IMA 优先**：用户指定库名/关键词（走 ima-mcp `search_knowledge`）；**本地可选**：文件夹路径（关键词检索）。缺失则跳过知识库核对并声明，行业常识按需 Web 检索兜底 |
| 项目文件夹 | 可选 | 会议记录所在目录。提供则自动检索：前序会议记录、`PDM口径台账-{项目名}.md`、前序核查报告——**命中须先报"已自动检索到 X 作为输入"，多候选列出让用户选，禁止猜** |
| 核查范围指令 | 可选 | 只核某几场/某主题（如"只对计费口径"）；批量形态下可指定部分记录走**快检模式**（仅①②③，零知识库/Web，不更新台账），默认全量 |

运行中信息缺口不阻塞执行，逐项登记入待核实清单。

**会议标识生成规则（v1.1.1）**：`会议标识 = 原始文件名去扩展名`（如 `第3次沟通会0914.md` → `第3次沟通会0914`）。文件名不含可辨日期时（无数字/日期串），提示用户补一个标识（建议 `YYYYMMDD-主题` 式），用户未给则以文件名全称兜底并在报告声明"标识无日期，排序按用户提供顺序"。批量排序优先文件名日期串；无日期串的文件按用户提供顺序置于有日期文件之后，总单注明排序依据。

## 三、执行流程（六步）

```
输入（会议记录 + 可选知识库/项目文件夹）
  │
  ├─ ①预处理与名称归一 ──变体聚类→权威名────→ 归一对照表
  │      ▼
  ├─ ②事实单元抽取 ────五类+发言人结构────→ 事实单元台账
  │      ▼
  ├─ ③文内交叉与常识扫描 ─五检验+两遍法──→ A/B 候选
  │      ▼
  ├─ ④知识库交叉核对 ──术语/惯例/常识三态──→ 证实/冲突/无覆盖
  │      ▼
  ├─ ⑤跨会议交叉核对 ──口径台账演化比对──→ 矛盾四分类+轨迹表
  │      ▼
  ├─ ⑥分级产出与台账更新 ─A/B/C+修订方案──→ 四件产出（净化版待确认）
  │
  输出：核查报告 html ｜ 修订方案 md ｜（确认后）净化修订版 md ｜ 核查标签清单 md ｜ 口径台账 md（更新）
```

### ① 预处理与名称归一

- **模式判定**：单会核查（无前序）/ 跨会议核查（检索到前序记录或台账）/ 下游净化（用户指明给 AI-DIG/Analysis 用 → 第⑥步必产净化版）。
- **文件体检**：说话人分离质量（分不出标 `UNKNOWN_SPEAKER`，不猜）、时间戳完整性、语气词保留（情绪信号密度，不清洗）。
- **名称归一预扫**：全文扫描公司名/产品名/器具名/人名/术语的**变体聚类**（驱动案例："路凯/陆凯/乐凯/陆海/露台"→路凯LOSCAM；"猪入单/中路单"→租入单），先归一再核查——否则后续所有机器比对失真。变体对照表进核查报告 C 类区。
- **中间态落盘** `checklist-{会议标识}.md`（编号/原文/类型/常识扫描[通过/移交]/知识库核对[未核/证实/冲突/无覆盖]/状态/已检轮次），中断可续。**位置（v1.1.1）＝与会议记录同目录**（非 TEMP 临时文件——需跨会话续作；运行全部完成且产出五件落盘后，checklist 转入"已完成"状态可清理，清理前自检 1 通过）。

### ② 事实单元抽取与发言人结构

- 五类抽取，优先级：**排他断言 > 结论性判断 > 数字 > 时间 > 名称**（互斥：一句只登记最高优先级类）。
- **发言人双方向结构**：客户方＋服务方各自 L1 显式署名 / L2 主题归属[推断] / L3 来源不明（不强行归属）；单信源记录声明"单一信源限制"。

### ③ 文内交叉与常识扫描

- 五检验：时间线收敛 / 数字自洽 / 前后矛盾 / 逻辑方向 / 跨章节数字一致。
- 常识可证伪扫描（两遍法）：全部断言过一遍"外行用常识能否推翻"——能推翻未验证 = B 类候选，标记"移交"后必须进入④⑤核对队列，不得静默流失。

### ④ 知识库交叉核对

- 通道：IMA（用户指定库名/关键词）→ 本地文件夹 → 均无则声明跳过 + Web 按需兜底。
- **核对三类对象**：①术语权威写法（确认归一结果）②业务惯例（如"租入再转租""按次计费""背靠背"是否行业常规）③客户行业常识（节拍/税率/单据流等）。
- **结果三态**：证实（引用库内条目）/ 冲突（登记 B 类候选）/ 无覆盖（进待核实，不强行定级）。
- **检索留痕强制**：检索词/知识库/命中条目/结论逐条登记进 checklist 与报告尾注，尾注与 checklist 对不上 = 自检不通过。

### ⑤ 跨会议交叉核对（核心增量）

- **读台账**（无则按八节模板创建，见 references/notcheck-method.md §六）：术语表／业务模式／计费规则／单据流／系统清单／组织与角色／待核实项／需求承诺与变更。
- **台账待核实项自动重验（v1.1.0 新增）**：读台账 §7 待核实项，本场记录有新证据的自动重验（对照核查），状态三态更新（仍待核/已证实/已证伪＋依据）；前场 [L2推断] 说话人身份被本场证实的，**归属升级 [L1]**（报告注明"归属升级"）。
- **逐主题比对**本场口径 vs 台账口径 → 产出**口径演化轨迹表**（主题｜前序口径｜本场口径｜演化类型｜**漂移方向[收敛/发散/横跳]**｜处置）。**发散**（各说各话）或**横跳**（反复≥2次回旧口径）的主题自动列为下游追问优先项（建议 Preparation-Analysis 遗留问题清单置顶）。
- **矛盾四分类**（判定顺序强制，防把术语歧义误判为业务反复；判定前先比对 method §十一错误模式库）：
  1. **术语歧义**——同一词两义（先查术语表，命中即归此类＋提"术语表补丁"）；
  2. **业务变更**——客户明示"以前是/现在是"，按时间线共存；
  3. **口误/记忆偏差**——数字小误差、一次性失忆，低危降权；
  4. **真矛盾**——以上都不是，同信源同主题不可共存 → 高危红旗。
- **深核对**：台账只存口径摘要＋"首次出处指针"（会议标识+时间戳），需要原文语境时回读前序记录原文，不全文摘抄控体积。
- **台账更新**：本场新口径入账（口径｜出处｜状态[稳定/漂移/矛盾/已收敛]），矛盾登记轨迹，已收敛条目标"已收敛＋收敛依据"。

### 批量执行（v1.1.0 新增，目录输入触发）

- **触发**：input 的会议记录为项目文件夹路径。
- **流程**：扫描文件夹内全部会议记录（md/docx/pdf/html/txt）→ 按文件名日期排序 → 逐件执行六步（第⑤步跨会议比对随序累积，台账逐场更新）。
- **跳过规则**：该记录同目录已有核查报告且记录文件无更新（mtime 未变）→ 默认跳过，总单标"沿用前次结论"；用户指定重核时重跑。
- **每件独立中间态**：`checklist-{会议标识}.md` 逐件落盘，中断可续（重入时读已完成件的总单行+台账，继续未完成件）。
- **批量确认单（v1.1.1）**：批量形态不逐件打断用户确认——逐件核查完成后，将全部修订方案汇总为一份**批量确认单**（每件一节：文件名｜A/B/C 计数｜待确认条目列表［仅②建议改写类，①直接订正与③保留批注默认放行］），用户按件或按条一次性确认；确认后逐件生成净化修订版。任一件用户未响应且急需下游消费时，该件只出不改（报告+标签清单+台账照常），净化版标记"待确认未生成"并告警下游。
- **总单产出**：`PDM会议核查审计总单-{项目名}-{YYYYMMDD}.md`——每行 `文件名｜核查结论（通过 / X处A·Y处B / 快检通过 / 沿用前次结论）｜标签清单路径｜报告路径｜台账更新摘要`，供下游与用户一口查看。
- **快检模式**：批量中用户指定的部分记录可走快检（仅①②③，零知识库/Web 核对，简化报告+修订方案，**不更新台账**防信息不全污染）；快检发现任何异常 → 报告尾建议"升级全量核查"。**快检 B 类标记纪律（v1.1.1）**：未经外核的 B 类条目一律标 `B*（快检未外核）`，与全量 B 视觉区分；下游消费 B* 时按"待升级核实的疑点"处理，不得与全量 B 同优先级进入追问清单（升级全量后 B* 转正或撤销）。

### ⑥ 分级产出与台账更新

- 证据分级（独立体系，售前/通用场景）：**K1** 知识库权威条目或文内自相矛盾 → 可支撑 A 类；**K2** 双源交叉 → 可支撑 A 类；**K3** 单一线索/逻辑失真 → 仅 B 类；检索无果 → 待核实（三解假设：清白/问题/中性＋核验动作）。
- 角色×错误矩阵：五分类定性（夸大/常识错/方向反/记忆偏差/无法归属）；**术语歧义导致的矛盾定④沟通偏差，不定②常识错误**——责任常在双向理解而非单方专业能力。
- 修订方案三分类：①**直接订正**（载体层转写错字错名，机械可自动）②**建议改写**（内容层，需用户逐条确认；**确认后的落点（v1.1.1）＝原文保留＋原地插入【已确认改写 #n：改写文本】批注**——内容层原文永不删除，改写文本以批注形态内嵌，证伪记录与修订结果并存）③**保留＋批注**（红旗标记，不改原文）。
- 产出五件（见 §四）；净化修订版**仅在用户确认修订方案后生成**。
- 自检 7 项（见 references/notcheck-method.md §九）。

## 四、输出规范（五件＋台账；批量另产总单）

| # | 产出 | 文件 | 说明 |
|---|------|------|------|
| 1 | 核查报告 | `{项目名}.会议记录核查报告-{会议标识}-{YYYYMMDD}.html` | 总览（计数+最重要发现+**核查时点声明**：知识库快照/Web 检索截止时点）→ A 类表 → B 类表 → C 类（名称对照+待核实三解假设）→ 跨会议口径演化轨迹表（含漂移方向）→ 角色×错误矩阵 → 尽调提示 → 尾注（知识库与 Web 检索留痕逐条登记，**来源按 K1-K3 分组罗列**） |
| 2 | 修订方案 | `{会议标识}-修订方案-{YYYYMMDD}.md` | 逐条：原文 → 问题 → 处置三分类 → 依据；用户确认入口 |
| 3 | 净化修订版 | `{会议标识}-净化修订版-{YYYYMMDD}.md` | **确认后生成**。载体层直接订正（附对照表）；内容层不改原文、原地插【核查批注 #n】；头部带**红旗摘要**（下游必读的口径警示 N 条） |
| 4 | 核查标签清单 | `{会议标识}-核查标签-{YYYYMMDD}.md` | **下游消费文件接口**：每行 `错误编号｜一句话摘要｜级别｜K级证据｜指向报告章节｜发言人[归属级]｜关联台账节`；快检件 B* 行级别列标"B*（快检未外核）"；Preparation-Analysis 产出三"追问类"/AI-DIG 待澄清清单按行导入 |
| 5 | 口径台账 | `PDM口径台账-{项目名}.md` | **项目级持久文件**（唯一不按日期命名），跨运行累积更新；八节结构 |
| — | 目录审计总单 | `PDM会议核查审计总单-{项目名}-{YYYYMMDD}.md` | **批量形态必产**：文件名｜核查结论｜标签清单路径｜报告路径｜台账更新摘要 |

措辞纪律：报告正文三分——"**记录称**"（会议记录原文主张）／"**台账载**"（本项目前序口径）／"**公开记录为**"（外部证据），不预判动机、不过度推断。

归档：默认与会议记录同目录（项目文件夹）；用户另有指定从其指定。

## 六、执行纪律（硬规则）

1. **原文零接触**：会议记录只读；净化版是新文件。
2. **内容层不改写**：净化版只订正载体层（转写错字错名）；内容层错误原地批注不改原文——证伪记录本身是证据。
3. **两段式确认**：修订方案未经用户确认，不产净化版。
4. **术语歧义优先排查**：任何跨会矛盾，先查术语表归类，再考虑业务反复。
5. **台账是项目记忆**：核查报告单份单次运行（不增量合并），台账跨运行持久累积；**每次运行必须同步台账**（新口径/矛盾/收敛三态落账）。
6. **命中先报告**：自动检索到前序记录/台账先报再用；多候选让用户选，禁止猜。
7. **分不出不猜、无覆盖不强判**：UNKNOWN_SPEAKER 不猜；知识库无覆盖进待核实不强行定级。
8. **检索留痕**：知识库与 Web 检索逐条登记，尾注对账；**检索深度纪律**（method §四）：每条候选 ≥2 轮、连续未命中换信息域、"检索无果"三条件不满足不得进待核实充当"已穷尽"。
9. **临时文件走系统 TEMP 目录**，不写同步盘工作区（文件锁坑）。
10. **批量防污染**：快检模式不更新台账；跳过件在总单显式标注"沿用前次结论"，不静默混入。
11. **台账独占写入（v1.1.1）**：同一台账文件同一时刻只允许一个 NOTE-CHECK 运行实例写入（台账是单写者文件）；检测到另一实例在写（台账"最近更新"时间戳晚于本次运行启动时间且非本实例所写）→ 暂停台账更新、报告告警，用户裁决后串行重跑第⑤⑥步。
12. **批注编号空间（v1.1.1）**：净化版批注 `#n` 与核查报告错误编号**同空间**（A-n/B-n/C-n 与待核实编号直接复用，不另起序号），下游凭标签清单"指向报告章节"列可反查。

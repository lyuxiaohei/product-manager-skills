# goal-creator · 无人值守任务命令生成

> 为无上下文执行会话生成任务命令。产出的命令必须**强于**当场口述——执行者什么都不知道，命令里没写的等于不存在。

## 生成前硬门（不满足不得动笔）

1. **汲取**：通读目标项目的交接文档／任务书／README-修订记录类基线；`git log --oneline -10` 看最近状态；该项目若有任务书文档（改造计划/施工细化），逐节读完——命令只指向不重复，避免双源。
2. **预置确定性**：任务含可预置的验证（校验脚本/命令）时，先在当前会话把**实测通过**的脚本落进项目，再把路径＋预期输出＋退出码写进命令——执行会话只跑不改写。
3. **基线锚定**：确认工作树干净，把当前 commit 哈希写进命令；执行会话开工先 `git status` 对账，脏树即停并报告。

## 命令必备九件（生成后逐项自检，缺一即未完成）

1. **绝对路径项目根声明**——一切相对路径的根
2. **必读源清单**（按序，含「未读完不得动手」）
3. **历史教训小节**——前批实测坑（锚点类/工具类/环境类）
4. **触发协议**——收到即开工、不向用户提问、缺输入按红线降级并报告
5. **任务序列**——小步推进＋**每步完成即验证**（早失败早停，不批量返工）
6. **红线**——不 push 远程／待定答案只落占位不臆造／失败即停留清单继续他项／范围外零接触／不报告未做过的验证
7. **验证命令**——预置脚本优先；写明预期输出与退出码
8. **DoD**＋执行报告落盘模板（路径写死）＋收尾摘要格式
9. **参数化范围**——$ARGUMENTS 留空＝全量，可传缩小范围

## 交付形态

- **主**：chat 内完整可复制块（```markdown 围栏包裹全文）。
- **可选**：落盘 `.claude/commands/goal.md` 项目命令（frontmatter：description＋$ARGUMENTS；正文即命令体）。
- 两形态**同源**：先写命令体，再包命令文件；严禁两处各写一份产生双源漂移。

## 反模式（三次实测教训，观察 #11）

- 丢绝对路径 → 执行会话找不到文件
- 缺历史教训 → 重踩前批已修的坑
- 内容弱于当前会话 → 执行质量漂移
- 让执行会话自写校验脚本 → 假失败/假通过之源
- 无 DoD／无报告模板 → 执行会话「感觉做完」即停

## 交付前自检

- [ ] 九件齐，逐项可勾
- [ ] 所有路径为绝对路径或在已声明根下
- [ ] 验证命令本会话实测过（做不到则明写「未验证」及原因）
- [ ] 执行者按文行事全程不需要问任何问题

# 修订原型 · PDM.Refinement-Prototype（技能链第 2 轮·V1.3）

链条：#3 初绘原型 PDM.Preparation-Prototype → **#4 修订原型 PDM.Refinement-Prototype（本技能）** → #5 评审彩排 PDM.Review-Rehearsal（修订＋PRD 同步完成后→下一次业务沟通前）。**链路图分环表示（2026-10-11 三环拍板）**：本技能在主流程图上按环分立为同名节点两处——修订·业务沟通环（第2~N次业务沟通环，含彩排检查站）／修订·AI评审环（三视角评审需修改驱动；真人开发评审已由 AI 三视角替代，2026-10-12 拍板）；各环只用自己的修订与 PRD 节点，不跨环共用（环内迭代复用）。沟通意见走主线（业务沟通→逐字稿→核查→修订）进来。窗口＝第 2~N 次业务沟通后 → 下次沟通前。与初绘一样只服务一件事：**下一轮会演示＋追问**。

命名规则（0929 拍板）：目录与 name 统一点分 PDM.Refinement-Prototype，中文短名「修订原型」写入 name 括号与触发词。

## 模型路由

> 落点表与验证纪律见 PDM.Model-Routing（单一事实源）；此处只写本技能分配，模型换代只改该文件。

- **写**：写旗舰——1M 全站一致性修订与 HTML 生成；样式仍一律引用 PDM.Spec-UI。
- **验·双通道**：①套餐 flash（原生视觉）——渲染截图按 R4 一致性清单走查＋Spec-UI 四端比对；②验 flash·思考开——修订记录↔落盘 diff 对账、结构/链接/字段一致性。均为一次性子代理，只回问题清单，禁止重写交付物。
- **可选·关键演示页**：二次会前用异族审（Kimi-K3）打磨——独立会话跑完＋硬边界（只改指定页，禁动口径/台账）。

## 输入（三件缺一不开工）

1. **新版会议材料**——本轮会议的 check 过纪要或会后待办拍板文档（NOTE-CHECK 产出或含逐条拍板的待办文档）。开工校验同初绘：带通过标记直接用；无标记询问用户，放行则产出头部注明「输入未过 check」，不确认退回。
2. **存量原型**——上一版原型（N 版，含菜单/页面/字段字典/演示数据/标注全件）。无存量原型＝初绘场景，退回用 PDM.Preparation-Prototype。
3. **项目口径基线**——决策台账（D 编号）或口径台账（NOTE-CHECK 维护）。没有则现场从存量 PRD/原型头部建最小台账再开工，不得无账改造。

任一缺失：停下告知用户缺什么，不降级开工。

**流程图缺位当场处置（v1.3.0）**：项目无主业务流程图时（非初绘入口——源码复刻/存量改造起步是合法入口，流程图常为交接遗留待办），R1 落账后**当场向用户提出**：补画（按 PDM.Preparation-Prototype S4 规格）或明示豁免并记入台账；不得把缺位静默带到 R7/彩排（彩排侧豁免出口见 PDM.Review-Rehearsal 输入例外）。

## 流程（7 步）

### R1 口径落账（先落账再动手）
通读会议材料，逐条口径落决策台账：新拍板（D 新号）／反转旧口径（引用旧 D 号＋注明反转）／存疑挂起（⏸ 标注、拍板前为红线）。**挂起项对应改动一律冻结不抢跑**（实战先例：计费方式 D-122 梳理未拍板前，全部计费/单价字段禁改）。落账结果给用户过目确认后进 R2。

### R2 改造任务分组（三分离）
按业务域把改动分组为 T 任务，每组显式三分离：
- **改造项**——逐条挂 D 编号依据；
- **确认项**——核对现状已合规的，零改动、执行记录登记「已确认」；
- **范围外项**——本轮不碰的（远期规划/挂起项/未指认页面），列出清单，失败清单不必记。
- **适用域裁定（v1.3.0，样式/口径类改造项）**——每条样式/口径类改造项显式裁定适用域（前台/后台/全站）写入任务行；范围外域必须落范围外清单；用户反馈措辞未限定域时**默认全站**，收窄到单域必须是一条显式拍板（留台账），不能是执行时的默认遗漏。

### R3 定点改造
只动 R2 改造项。**旧口径反转必须显式留痕**：页面注记＋台账反转记录（实战先例：退租入库从自由新建反转为两步形态，同时注记旧口径 D 号已反转）。样式一律引用 PDM.Spec-UI，同初绘。

### R4 全站一致性同步（本技能核心，初绘没有的步骤）
每处改造按**六层清单**核同步，漏一层即"改崩"：
1. **菜单/导航**——菜单项、selected 高亮、组序、死链 0；**多端复刻分组派生（v1.3.0）**：复刻对象为多端后台系统时，演示导航（侧边栏/页签）分组必须从**各端路由表**（router.tsx 或等价物）逐端派生——每组＝一个端、组名标注端角色（端名＋页数）、同构复用页在所属端挂复用注记；两端同名的生产菜单组名不得单独充当分组标签（归属模糊信号）；校验断言按「每端页数」而非「总项数」表达；源码行号写进组头 tooltip；
2. **页面双层**——列表页＋新建/编辑表单（或独立模板页）字段同步；
3. **字段字典**（A05 类）——新增/改名字段落字典；
4. **演示数据**（demo-data 类）——新增字段补演示行、值域与页面一致；**值源可复现性（v1.3.0）**：凡新增/改动字段并声明取值来源（档案联动/枚举/带出链）——①演示值必须 ∈ 该来源取值域（来源实体记录中存在该值、或能在来源页选中）；②文档/标注中「对应 XX 档案/来源」类断言逐条回核；③走查断言至少一条从来源页出发（选来源→断言能产出演示值），不只验下游同值——「字段有了来源机制」≠「演示值可由来源产生」，对账必须双向闭合；
5. **标注层**（A03/A04 类）——新增/改动元素补标注键重注入，注入告警 0；
6. **域覆盖（v1.3.0）**——凡 R2 适用域＝全站的改造，逐域（前台/后台）点名核执行；同名字段（如视图菜单角色前缀）逐域核对已删/已改，不许"前台生效即记已删"。

### R5 产出增量更新（四件＋版本记录）
原型（新版本号）／功能对照表（客户态度列刷新）／问题清单（三源合并：本轮没答清＋新待定＋改造中画不下去的点）／决策台账（R1 已落，收尾核对无漏账）。**版本记录（V1.2 起）**：原型根 README-修订记录.md 同轮更新——**当前版本行**递增（按 VERSIONING.md §8 语义：方案性变更 MAJOR／兼容新增 MINOR／修正 PATCH）＋**变更履历表**续写一行［版本／日期／变更摘要／触发来源］，触发来源写本轮驱动来源（会议纪要／彩排问题清单 V{x.y.z} 等）；主业务流程图.html 头部同轮写版本注释行。

### R6 PRD 同步（V1.2 起，必经步）
修订落盘后**随即使用 PDM.PRD-Generator（V2.0）做增量更新**——不论本轮修订由谁驱动（业务沟通意见／彩排人判未过／AI三视角评审需修改），此步**不可跳过**：主流程变更走对应章节增量，页面级细节只更新功能清单/字段表，PRD 头部版本注释记联动来源（随原型 V{x.y.z} 同步）。PRD 与原型独立编号。

### R7 交彩排（2026-10-11 起）
PRD 同步完成后交 PDM.Review-Rehearsal 评审彩排——以业务评审方视角对方案出《彩排问题清单》交人判定；人判未过则以清单为返修输入回到 R1（口径落账：清单问题逐条挂待办），修完（含 R6 PRD 同步）再彩排，循环直至人判通过、放行下一轮业务沟通（业务评审即沟通本身）；AI评审环的需修改意见同样走 R1→R6→再交三视角评审（不经彩排，彩排为业务沟通环检查站）。

## 纪律

- **不越界**：范围外项零接触；挂起红线拍板前冻结。
- **不臆造**：同初绘——会议材料里没有的不进改造。
- **改前快照**：git 提交或备份（备份放原型目录外），单写者互斥。
- **失败跳过留档继续**：锚点缺失/结构不符，跳过→失败清单→继续，禁猜测性改写。
- **旧口径不静默删除**：反转即留痕，演进史是证据。

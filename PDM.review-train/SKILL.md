# PDM.review-train · PDM 评审技能校准 v1.2.2

> 定位：**用真实人类评审数据校准 PDM 评审技能族的元技能**。回答一个核心问题："真人评审会抓的问题，我的 AI 评审技能抓得住吗？抓不住的差在哪？怎么改？"
> 被测对象：PDM.Review-Developer / PDM.Review-Tester / PDM.Review-Director / PDM.Review-Summary 四件套（下称"被测技能"）。
> 本技能只产出升级建议方案，**绝不直接修改任何被测技能文件**——建议方案按 rc 评审流程（rc1→rc4）收敛后由用户落盘。

## 一、适用场景与输入

| 参数 | 必需 | 说明 |
|------|------|------|
| 评审会议纪要 | ✅ | 结构化纪要；同场原文/逐字稿强烈建议（无则金标准降级，仅纪要结论层）。md/docx/pdf/html，扫描件走 vinfield-PDF OCR 纪律 |
| 评审前 PRD | 可选 | 评审时点前的 PRD（用户直供）。与评审前原型或关系，≥1 即构成"评审前材料集"，触发快照模式（含/不含会后材料集分完整版/无会后版） |
| 评审前原型 | 可选 | 评审时点前原型（PNG/HTML），与评审前 PRD 或关系。快照模式直供全集参与盲测（无锚点映射） |
| 会后 PRD | 可选* | 会议之后版本的 PRD。**会后材料集（会后 PRD∨会后原型≥1）为现状对照/回放·完整版/快照·完整版必需**；目录内含多版本时触发锚定重建（见①）。*金标准积累模式不需要 |
| 会后原型 | 可选 | 会后原型库（PNG/HTML），与会后 PRD 或关系构成会后材料集 |
| 项目文件夹 | 可选 | 提供则检索 PDM校准台账-{项目名}.md 跨场累积证据，并可自动检索补齐输入（命中先报"已自动检索到 X 作为输入"） |
| 视角范围 | 可选 | 默认四件套全跑；可指定子集（如仅 Developer，快测用） |

不适用：①售前链路数据（Preparation 系列的改进不走本技能）；②**仅纪要单场**（无任何 PRD/原型）：不拒收，转金标准积累模式——单跑③金标准提取＋⑥受限四步（模式聚类→静态覆盖比对→模式库证据池累积→受限触发），不跑盲测/核验/对账，diff 级升级建议不触发，台账标"无对照场"不入漏报类证据池；后续补齐材料可重跑升模式（纪律 7）；③**被测技能的「纪要集群模式」产出**：视角无关、无三视角对照测点，不在本技能校准范围——集群场次一律拒收，其质量改进另行处理（②与③为不同概念：单场原始纪要=GS 可提取，集群模式产出=无测点）。

## 二、执行流程（六步，顺序强制——盲测先行＋上下文隔离防锚定污染）

```
输入
  ├─ ①预处理与模式判定 ──纪要分级/变体归一/材料形态判定（六态）/锚定·验证/台账检索──→ 模式声明
  ▼
  ②盲测（先跑先锁＋上下文隔离）──被测技能 × 材料集──→ AI问题清单 落盘锁定
  ▼
  ③金标准提取 ──纪要拍板+逐字稿过程──→ 人类发现清单 GS-n
  ▼
  ④落地核验 ──GS × 会后材料集（无会后变体/金标准积累模式跳过）──→ 未落地(有效测点)/部分落地(半有效)/已落地(不可测)
  ▼
  ⑤对账 ──AI清单 × GS──→ 命中/漏报/不可测漏报/AI独有/待复核
  ▼
  ⑥归因与双证据池 ──聚类＋台账双池累积──→ 校准快报 / 对照版·模式库版升级方案
```

### ① 预处理与模式判定

- **纪要格式分级**：按被测技能【会议纪要处理】①的判定规则（结构化/AI重构版/智能优化版转写）分级登记；同音变体先归一（借 PDM.NOTE-CHECK 名称归一方法，如"若翼→若依"）。**浅层处理定界**：格式分级与变体归一仅做格式特征识别与专名归一，不提取、不登记任何问题语义（拍板内容/质疑/缺陷表述），不构成纪律 2 所指的深读；**台账检索同属浅层**——仅读取"是否命中＋场次清单"用于模式声明，不读入台账中的 GS 明细与归因内容（需引用明细的环节在②落盘锁定后进行）；AI 重构版判定存疑、需语义级阅读才能定级时，该分级步骤转一次性子代理执行，主上下文只消费分级结论。
- **材料形态判定（先于锚定）**：用户直供评审前材料集（评审前 PRD∨原型≥1）→ 快照模式（含会后材料集=完整版/不含=无会后版），跳过锚定重建，转**锚点验证**；仅纪要无任何材料 → 金标准积累模式（本步裁剪见①段末）；**仅会后材料 → 直接判现状对照模式**（无锚定可做，不进锚定重建路径）；其余（多版本目录）走锚定重建路径判定回放。**判定依据：用户显式指定 > 自动检索推断**（沿用 vinfield 惯例）；快照·无会后场与回放·无会后场经项目文件夹自动检索命中会后材料集 → 分别升格快照·完整版/回放·完整版，报告声明检索来源。
- **锚点验证（快照模式专属，防用户指错版本）**：验证对象=评审前材料集整体（PRD∨原型，界面元素锚点天然落在原型上）。三分支：①**有逐字稿＋多版本在场**——对比验证：他版命中率显著更高（≥2 锚点或 ≥30%）→ 列出对比交用户确认（多候选禁猜），用户坚持直供版则照用＋声明风险；锚点总数 <5 → 对比不具统计意义，按分支②口径列出明细交用户确认；②**有逐字稿＋无他版**——单版本置信检查，沿用绝对置信度双条件（命中率 ≥60% 且锚点总数 ≥5）；不过 → 列出命中率明细交用户确认，用户坚持则照用＋报告声明"锚点验证未通过"，**此路径不触发自动降级**（快照材料系直供，无更低模式可降，自动降级将制造材料时点错位）；③**无逐字稿**——采信用户指定，报告声明"未经锚点验证"。锚点提取须深读逐字稿，**必须在一次性子代理中执行**（纪律同锚定深读隔离：输入=逐字稿＋各版本路径，产出=锚点命中率表（仅材料指称，禁问题语义），落盘后子代理上下文即弃）。
- **锚定重建（回放条件探测，仅多版本目录场触发）**：项目文件夹内 PRD 目录含多版本时（用户指定目录，或按输入表"项目文件夹"参数自动检索命中），从逐字稿提取**材料指称锚点**（发言人描述的界面元素/字段/规则/交互态——他们眼前的东西），与各版本匹配。**判定双门槛**：①相对显著性——逐版本计算锚点命中率，最高且显著高于次高（差距 ≥2 个锚点或 ≥30%）者为 T0 候选；②绝对置信度——唯一命中锚点数 ÷ 逐字稿材料指称总数 <60%，或锚点总数 <5 → T0 重建置信不足。任一门槛不过即判「锚定失败」，自动降级现状对照模式，**不得强行指定**。T0 判定结论、各版本命中率与置信度明细写入报告首行"资料范围"；两阈值为启发式，首跑后校准。**T0 保真度声明**：T0 为"早期 PRD + 锚点映射原型子集"的重建物，非原始快照；原型仅覆盖锚点命中部分，未命中页面的缺失在"资料范围"显式声明。**锚定深读隔离（强制）**：锚点提取须深读逐字稿，必须在一次性子代理中执行——子代理输入=逐字稿文件路径+各版本 PRD 文件路径，产出=《T0 材料集清单+锚点映射表》（仅材料指称，禁问题语义），**产出落盘后子代理上下文即弃**；**主执行上下文在②盲测落盘锁定之前禁止读入纪要/逐字稿的问题语义，只消费清单文件；②锁定后，③④⑤⑥ 照常深读逐字稿（盲测已锁，无污染通路）**。
  - **防污染纪律**：锚点只登记"材料是什么"（弹窗态/字段名/页面结构），**禁止登记任何问题语义**（好不好/有没有缺陷）——问题语义进入会污染后续盲测独立性。
- **模式判定（六态，判定优先级自上而下，互斥）**：
  - **快照·完整版**：直供评审前材料集＋会后材料集 → 盲测对象=评审前真实快照（原型直供全集）。关涉评审前材料全类型 GS 均为有效测点；④核验对象=会后材料集，结果仅输出为《版本链断点清单》不改测点；归因类目「T0 重建遗漏」不适用（真实快照，风险源=指认错版本，锚点验证对冲）。
  - **快照·无会后版**：直供评审前材料集、无会后 → 测点口径同完整版；④跳过（无核验对象），断点清单不产（报告"资料范围"声明）；正常入漏报类证据池（有盲测有对照=合格对照场）。经自动检索命中会后材料集→升格完整版（见材料形态判定）。
  - **回放·完整版**：锚定重建成功＋会后材料集 → 盲测对象=T0 重建材料。关涉 T0 材料的全类型 GS 均为有效测点；④核验对象=会后最新版，仅输出断点清单。
  - **回放·无会后版**：锚定重建成功、无会后 → 测点口径同上（测点有效性来自 T0 材料）；④跳过，断点清单不产（声明）；正常入漏报类证据池（与快照·无会后版对称）。经自动检索命中会后材料集→升格完整版。
  - **现状对照模式**：无评审前材料可锚定（含锚定失败/单版本/仅会后直接进入）＋会后材料集 → 盲测对象=会后材料。GS 需经④落地核验分堆，仅残差与半有效测点的缺口项为有效测点。
  - **金标准积累模式**：仅纪要 → 不跑②；③照常（涉及对象标"对象未经材料核验"）；④⑤跳过；⑥替换为受限四步（见⑥）。不产生漏报归因、不触发 diff 级升级建议；台账标"无对照场"不入漏报类证据池，标"待补材料"留升模式通道。
  - **兜底**：多版本目录场锚定失败且无会后材料集 → 归金标准积累模式，报告标"锚定失败降级，建议补材料"（此刻有效输入仅剩纪要）。
  - 非材料类 GS（涉及对象为空——纯业务背景/外部环境讨论，不指向任何材料对象）不参与任何模式核验与对账，单列标"非材料类"。
- **金标准积累模式下①裁剪**：仅执行纪要格式分级＋同音变体归一＋台账检索（浅层三项），无材料形态判定与锚点环节（无材料可判）；模式直接落位判定矩阵末行。
- 台账检索与模式声明写入报告首行"资料范围"。

### ② 盲测（先跑先锁＋上下文隔离）

- 按被测技能各自的 SKILL.md 方法执行评审。**顺序**：Developer / Tester / Director 三视角**逻辑并行**——仅以材料集为输入、互不引用；三视角齐备后跑 Summary（其输入为三份视角报告，属流程必需，非串行依赖）。全程**不给纪要、不给逐字稿、不给任何会议信息**。**执行上下文隔离（强制）**：盲测在未接触纪要/逐字稿问题语义的干净上下文运行——**默认每视角独立子代理**（输入=材料文件路径+显式落盘路径+目录覆盖指令），**备选**用户分会话跑后带回文件；主上下文仅完成①浅层处理（格式分级/变体归一/台账检索，见①定界）而未读入问题语义时，允许同会话直跑三视角，但须显式声明"仅以材料集为输入，忽略对话中已有视角报告"（防视角互锚）；**主上下文已读入纪要/逐字稿问题语义的（含①锚定深读未经子代理的任何读入），禁止本对话自跑盲测，一律转子代理或分会话，违规跑出的盲测结果作废重跑**。**Summary 盲测测点单列**：不参与召回对账（其问题清单来自三视角，纳入将重复计数）；单列核验「合并去重完整性」——三视角问题条目 vs Summary 总清单逐条比对，缺失条目出**《汇总丢条清单》**，归因类目「汇总遗漏」（Summary 专属，不入漏报归因）。
- 原型形态：回放模式（两变体）PNG 按①锚点映射取子集；快照模式（两变体）评审前原型直供全集（无映射）；HTML 直接给。**PRD/原型对称缺席机制（所有盲测类模式通用）**：原型缺席（有 PRD）→ 盲测基于 PRD 运行，关涉原型页面的 GS 单列"原型维度缺席"不参与对账，指标行加注"不含原型维度"；PRD 缺席（有原型）→ 盲测基于原型运行（可查字段/交互态/规则层问题，业务背景维度降级），关涉 PRD 章节的 GS 单列"PRD 维度缺席"不参与对账，指标行加注"不含 PRD 维度"；两缺俱无=该时点材料集缺席→场次降级（见模式判定）。均无时不得使用逐字稿口述段（口述段含问题语义，构成盲测污染）。金标准积累模式无盲测环节，本步整体跳过（落盘锁定与完整性预检随之下线）。
- **落盘锁定**：三视角报告+汇总判定按被测技能**命名**规则落盘 `{输出根}/PDM技能训练/盲测-{需求名}/`——本技能运行期间**覆盖被测技能默认路径 `./PRD评审/`，覆盖指令写入盲测子代理提示词**（文件名保持 `PRD评审-开发视角-*` 等原样，仅改目录）；未能按覆盖路径落盘的，跑完统一搬入并登记，**不得两处并存**。对账以落盘文件为唯一依据（不以对话记忆为准）；**对账前执行落盘完整性预检（按①模式声明中"视角范围"声明的 N 份盲测报告+金标准齐备性，四件套全跑时 N=4），缺件即中止对账并报缺**。用户分会话跑盲测时，带回文件放入同目录。

### ③ 金标准提取（人类发现清单）

从纪要+逐字稿提取，双源纪律（结构化纪要供结论框架，逐字稿供过程补漏——纪要未收录的质疑、追问、未结论讨论都是发现）：

| 字段 | 说明 |
|------|------|
| GS-{n} | 全局编号 |
| 发现内容 | 人类指出的缺陷/质疑/取舍点（一句话） |
| 类型 | 问题发现（材料有毛病）/ 质疑追问（未结论）/ 拍板取舍（新增·修改·裁剪决策） |
| 结论 | 拍板（含内容）/ 推迟 / 开放（未结论） |
| 出处 | 材料+时间戳（逐字稿段号/发言人） |
| 涉及对象 | PRD 章节 / 原型页面 / 接口·系统；为空（纯业务背景/外部环境讨论，不指向任何材料对象）→ 标"非材料类"，不参与核验与对账；金标准积累模式（无材料场）按纪要原文表述登记，逐条标"对象未经材料核验" |

提取纪律：只登记"人类实际说了的"，禁止脑补人类应该发现的问题；发言人归属不明的标注（不用于责任判定，仅溯源）。

### ④ 落地核验（材料类全类型 GS）

GS（**全部三类：问题发现 / 质疑追问 / 拍板取舍**）× 会后材料集（会后最新版 PRD/原型）逐条核验，核验口径按类型分层：**问题发现类**按"该缺陷是否已在会后材料中修复"判定；**质疑追问类**按"该质疑是否已被回应/消解"判定（会后版本已对该开放问题补充定义的，视为**已自愈**）；**拍板取舍类**按"该决策是否已落文档"判定。结果三态：✅已落地 / ⚠️部分落地 / ❌未落地。非材料类 GS（见③涉及对象）不参与核验。

- 现状对照模式：**❌未落地 = 残差 = 有效测点**（问题仍在材料中，被测技能理应报出）；**✅已落地 = 不可测点**（问题已不存在，技能不报是对的——**对账时单独归类，不计漏报**；含质疑类"已自愈"）；**⚠️部分落地 = 半有效测点**——核验时登记「缺口项」，缺口项按有效测点参与对账、已消解部分按不可测点归类；该条对账结果标注"(部分落地)"，⑥ 归因时区分「因缺口隐蔽而漏报」与「技能缺陷漏报」。
- 快照（两变体）与回放·完整版：④核验结果仅输出为《版本链断点清单》（拍板未落文档的真实案例，副产品交付物——本身就是被测技能《会后未落文档清单》机制的实证素材），**不改测点有效性**。
- 已知现象预登记：日期晚于会议的版本 ≠ 承接了会议拍板（驱动案例：0127 字典拍板"内嵌表格/新页面"，02-02 修订版 0 命中，"弹窗"反增）。断点是常态预期，不是异常。
- **无会后变体（快照·无会后版/回放·无会后版）跳过本步**（无核验对象），《版本链断点清单》不产，报告"资料范围"声明（"已知现象预登记"段随之不适用）；金标准积累模式跳过本步。

### ⑤ 对账（AI 清单 × GS）

语义匹配（同一问题对象即算对应，非字面匹配）。**匹配存疑的标"待人工复核"并在对账表单列，暂不计入召回率分子与分母**，指标行注明"含 N 条待复核"，复核完成后回填：

| 类别 | 定义 | 去向 |
|------|------|------|
| 命中 | 有效测点有 AI 对应条目 | 召回证据 |
| 漏报 | 有效测点无 AI 对应 | **召回缺口 → ⑥归因** |
| 不可测漏报 | 仅现状模式：已落地 GS 无 AI 对应 | 标注不计漏报 |
| AI 独有 | AI 报出但 GS 无 | **分拣清单**：真问题（人类漏审）/ 过度报警 / 待判——人工抽判，不自动判误报 |

指标：有效召回率 = 命中/(命中+漏报)，分母含半有效测点的缺口项（已消解部分与不可测点不计）；AI 独有数；分拣后过度报警数（误报率上界素材）；待复核 N 条单列。维度缺席场指标行按对称缺席机制加注（"不含原型维度"/"不含 PRD 维度"，见②）。金标准积累模式跳过本步（无 AI 清单无对账）。

### ⑥ 归因与双证据池累积

**漏报归因（逐条，五类）**：
- 检查项缺失：被测技能现有维度未覆盖该问题类型 → **增补候选（最高优先级）**。例：GS"凭据明文入库"，Developer 五维无凭据项 → 维度未覆盖
- 穷尽性不足：维度覆盖但未逐项查到 → 执行强化建议（checklist 化/留痕规则）。例：GS"时区未定义"，Developer 维度 2 含"时间逻辑：时区"但盲测报告未查 → 已覆盖未查到
- 粒度错配：AI 报了但颗粒度太粗对不上 GS → 输出粒度校准
- 材料边界：盲测材料确实看不到（现场演示/口述才暴露）→ 剔除并登记
- **T0 重建遗漏**（回放两变体专属）：T0 为重建近似物，盲测材料缺料（原型未命中页面缺失等）导致的漏报——**不计入技能缺陷**，与「材料边界」并列

**误报归因**（仅针对 ⑤ 分拣确认为「过度报警」的条目）：阈值过敏感 / 表述歧义（PRD 写了被误读）/ 规则误用。「真问题（人类漏审）」归 ⑤ AI 独有分拣的价值项，不入本类。**汇总遗漏归因**（Summary 专属测点）：《汇总丢条清单》条目归因（合并规则执行偏差/去重误合并），入 Summary 升级建议。

**金标准积累模式⑥替换为受限四步**（对照场⑥不变）：⑥-1 人类发现模式聚类（GS 按问题模式归类：边界条件/数据一致性/权限遗漏等）→ ⑥-2 静态覆盖比对（候选模式 × 被测技能 SKILL.md 含 references/ 逐条映射，三态判定：未覆盖→候选增补条目/已覆盖→登记防冗余不入建议/存疑→留观；仅判定文本层面，不预测执行命中；无盲测场无隔离需求，主上下文直接执行；《模式覆盖比对表》并入金标准文件末节）→ ⑥-3 模式库证据池累积＋触发判定 → ⑥-4 受限升级方案产出（触发时）。

**台账累积**：`PDM校准台账-{项目名}.md` 逐场追加（场次×GS×对账结果×归因），升级建议的证据池。**双证据池**：
- **漏报类证据池**——对照场漏报归因证据，复现判定键三要素=同一被测技能 × 同一归因类别 × 同类问题模式（具体对象可不同）；无逐字稿场次（GS 降级为纪要结论层）的有效召回率标注"GS 降级，仅供参考"，不入本池入场券。
- **模式库证据池**——人类发现模式证据，复现判定键两要素=同一被测技能 × 同类发现模式（无归因维度）；**两源入池，分层键=证据形态**（与场类型无关）：**逐字稿场**（无论对照/仅纪要）全效力；**纪要级场**（无论对照/仅纪要，结构化非 AI 重构）封顶建议级（强烈建议级须 ≥1 场逐字稿场支撑）；**AI 重构版/智能优化版转写不入**。AI 独有分拣清单的人工抽判结论（真问题/过度报警/待判）由用户抽判后回填台账对应场次行，作为误报归因与「人类评审发现模式库」的证据。
- **台账分区**：单场次登记行＋漏报类证据汇总区＋模式库证据汇总区，两池分开计数互不混算。

**证据强度三级**：单场孤例=观察级；2 场复现=建议级；3 场及以上=强烈建议级。**累积细则**：①复现判定按各池复现键执行；②「场次复现」=同一建议项（按所属池复现键判同）在 N 个不同场次各自获得证据支撑（同场多次出现仍计 1 场）；③强度按支撑场次数定级（1/2/≥3 场=观察级/建议级/强烈建议级）。

**输出触发**：单场跑完出校准快报（含全部对账明细+观察级建议）＋**《升级建议草稿》（每场必产，见输出规范 7）**；**漏报类证据池**达"建议级及以上"的升级建议项累计 ≥3 条 → 产出**对照版**方案；**模式库证据池**达"建议级及以上"且"未覆盖"的模式条目 ≥3 条 → 产出**模式库版**方案（两触发并行独立计数）。**"未覆盖"判定按证据来源分径**：仅纪要场条目=⑥-2 静态覆盖比对三态结论；对照场条目=盲测执行命中判定——AI 漏报该模式（该模式有 GS 且盲测未报出对应条目）即"未覆盖"，AI 命中即"已覆盖"。**同轮去重**：同一模式已入当轮对照版 diff 的，模式库池该条目标"已入对照版"，不计入模式库版触发（对照版 diff 为更强形态，模式库版不再重复收载）。**批量训练纪律**：台账单写者，批量场次逐场串行，禁止并行实例；每场必产《升级建议草稿》（输出规范 7）；正式方案产出取双模式之一——**即时触发**（默认：达触发阈值即出，rc 链顺延）或**延迟合并**（台账批模式声明生效时：批末按复现键聚簇合并各场草稿出正式版，任何模式达强烈建议级可经用户拍板单独提前合入）；证据继续累积，再达触发产下一份；同场重跑全量替换该场台账行（该场草稿同步重产替换），已产方案受影响条目在下一份修正；批次标记 B{n} 为台账可选列，不参与判定。

## 四、执行纪律（硬规则）

1. **只出建议不动技能**：升级建议方案走 rc 评审，由用户确认落盘；本技能运行全程不写任何被测技能文件。
2. **盲测先行且上下文隔离（盲测类模式适用——快照/回放/现状对照）**：顺序不可倒置；对账只认落盘文件。金标准提取不得早于盲测锁定完成。盲测执行上下文在②落盘锁定前不得读入纪要/逐字稿的**问题语义**（拍板内容/质疑/缺陷表述——①格式分级、变体归一与台账检索属浅层处理不在此列，锚定深读与锚点验证提取已转子代理）；本会话已读入问题语义时，盲测必须转干净子代理或用户分会话执行，违规跑出的盲测结果作废重跑。②锁定后③④⑤⑥照常深读逐字稿，无污染通路。金标准积累模式无盲测，无污染对象，主上下文可直接深读纪要。
3. **锚点无问题语义**：①的锚定重建与锚点验证只登记材料指称；发现问题语义混入锚点表即中止重来。
4. **AI 独有不自动判误报**：一律进分拣清单人工抽判（AI 对、人类漏审是技能价值，不是噪声）。
5. **不可测点显式分堆**：现状模式已落地 GS（含质疑类"已自愈"）标"不可测漏报"；⚠️部分落地标"(部分落地)"，仅缺口项入有效分母；严禁混入漏报计数虚降召回率；快照（两变体）/回放（两变体）模式无此堆。
6. **归因必锚证据**：每条建议带 GS 编号+场次+原文出处；无证据的建议进"不建议动清单"。
7. **单场单次运行**：同一纪要重跑全量替换不增量合并；多场各产一套，文件名需求名+轮次（-R2/-R3）+日期区分。金标准积累场补齐材料后重跑=按新输入重新判定模式并全量替换该场次（属重跑非增量，不违本条）。
8. **敏感数据本地化**：内网人名/排期/系统名仅存在于本地产出，禁止外发；对外引用需脱敏。
9. **临时文件走系统 TEMP 目录**（同步盘锁坑）。
10. **台账单写者**：同项目台账同一时刻仅一个实例写入（沿用 PDM.NOTE-CHECK 纪律 11 机制）；批量训练场次逐场串行执行。

# 文档结构规则 V7.2

定义版本PRD的章节编排：模块级 3 段（标准模式）和 4 步业务建模（评审模式）。

**V7.2 重构**：评审模式章节重组——页面清单提前（二）、AC紧邻每模块UC（三）、异常并入流程（四.5）、状态机改为可选（六）。

**V7.1 新增**：评审模式章节结构 + 页面清单规范 + ER图规范 + 占位处理规则。

**V7.0 重构**（相对 V6.0）：页面级 6 节 → 模块级 3 段；引入 UC/AC/代号编号体系；可选章节 4 个 → 2 个；非功能需求并入核心流程。

```
│   └── 1.2 本次不做（Out of Scope）
├── 二.1 角色列表                   [必选，含代号列]

├── 二.{代号}.2 功能用例与验收      [必选，每模块重复]
│   ├── 功能用例表（UC-{代号}-{n}）
│   ├── 验收标准（AC-{代号}-{n} + 对应用例）
│   └── 测试账号（全文仅首个模块）
├── 三.{代号} 核心流程              [必选，每模块重复]
│   ├── 3.{代号}.1 主流程（Mermaid）
│   ├── 3.{代号}.2 状态流转（含守卫条件）
│   └── 3.{代号}.3 异常与边界（功能异常 + 非功能）
├── 四.{代号} 数据流向              [必选，每模块重复]
│   ├── 4.{代号}.1 数据责任（角色×动作，中文动词）
│   └── 4.{代号}.2 字段说明（9列，首列字段中文名）
│
├── {N}、单据流转                   [可选 · 有核心实体时]
├── {N+1}、接口时序                 [可选 · 跨系统时]
└── {N+2}、实时通信                 [可选 · 有实时推送时]
```

## 必选章节

### 一、范围边界

放在文档最前，让读者 1 分钟内理解本次做什么。

- **1.1 In Scope**：`编号 / 模块 / 代号 / 功能点 / 优先级 / 说明`
- **1.2 Out of Scope**：列表形式，每项附原因

### 二.1 角色列表

`角色 / 代号 / 说明`。代号全局唯一，后续 UC/AC/CRUD 全部引用。

### 模块 3 段（二~四）

每个本次范围内的模块重复输出 3 段，使用 `templates/prd-module-section.md`。模块编排顺序见下文。

## 可选章节

| 章节 | 生成条件 | 来源 |
|------|----------|------|
| 单据流转 | 有核心业务实体（订单/审批/商品上架） | 业务逻辑清单的核心单据流转 |
| 接口时序 | 涉及跨系统交互（前端→网关→服务→DB/MQ） | 业务逻辑清单的系统交互时序 |
| 实时通信 | 有 WebSocket/长连接推送（IM/客服/协作） | 业务逻辑清单的系统交互时序（推送链路） |

> **角色与架构**：已并入「二.1 角色列表」，不再独立成章（角色定义即角色列表，交互矩阵按需并入相关模块的核心流程）。
>
> **非功能需求**：已并入模块级「三.{代号}.3 异常与边界」的非功能子表，不再独立成章。
>
> **数据模型**：数据结构并入「四.{代号} 数据流向」，不单独成章。

## 模块编排顺序

模块按**用户操作路径**排序，而非按文件名/层级：

### 推荐顺序

1. **账号与登录**（A）— 用户最先接触
2. **个人中心**（P）— 登录后首个管理页
3. **商品与浏览**（P/G）— 核心浏览路径
4. **购物车**（C）
5. **下单与支付**（O）— 转化路径
6. **订单管理/售后**（O）— 售后路径

### 编排原则

- 同一操作流程的模块相邻（登录+注册、下单+支付）
- 先基础后高级，先主流程后辅助
- 模块代号取英文名首字母，全局唯一、不冲突

## 编号规则

| 对象 | 格式 | 示例 |
|------|------|------|
| 章节号（版本级） | 中文数字 | 一、二、三 |
| 章节号（模块级） | `{版本级章节}.{代号}.{子节}` | 二.P.2、三.O.1 |
| 功能用例 | `UC-{代号}-{序号}` | UC-P-01 |
| 验收标准 | `AC-{代号}-{序号}` | AC-P-02 |
| 业务规则 | `RULE-{代号}-{序号}` | RULE-P-001 |

**约束**：
- 所有标题必须带编号
- 模块代号全局唯一（Product→P，Order→O，Auth→A）
- UC↔AC 通过验收表「对应用例」列绑定，一条 UC 可对多条 AC
- 同一规则只编号一次

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 按文件名排序模块 | 按用户操作路径排序 |
| 验收标准不填「对应用例」 | 每条 AC 绑定到 UC |
| 测试账号每模块重复 | 全文仅首个模块输出，其余引用 |
| 统计指标单列章节 | 作为字段行写入字段说明表 |
| 简单模块硬凑满 3 段所有子节 | 按需省略，不留空占位 |
| 编号跨模块冲突 | 模块代号全局唯一 |
| 非功能需求单列章节 | 并入「异常与边界」非功能子表 |

## 评审模式专有规则 [V7.1]

### 页面清单规范

| 列 | 规则 |
|----|------|
| 页面名称 | 用中文名，待补充页面用 **粗体** |
| 文件名 | 预期的 HTML 文件名，待补充页面用 **粗体** |
| 路由 | 预期的 URL 路径 |
| 状态 | ✅已有原型 或 ❌待补充 |
| 评审点 | 对应评审议题编号 |

### 占位处理规则

对于缺失原型的页面：

1. 在页面清单中标注 ❌
2. 在「待补充页面骨架」子节中创建占位条目
3. 写 `> **说明**: {已知信息}` 描述该页面与评审议题的关系
4. 写 `**【请补充：页面布局、字段、交互细节】**` 作为占位标记
5. **严禁编造**未在源码中出现的字段、布局或交互

### ER 图规范

- 使用 Mermaid `erDiagram` 语法
- 实体间关系用 `||--o{`（一对多）等形式
- 每个实体列出关键字段，标注 PK/FK
- **新增字段用粗体标记**，如 `**public_email**`
- 字段说明表同步标注新增字段

### 页面跳转关系图

- 使用 Mermaid `flowchart LR`（横向布局）
- 节点格式：`PageName[中文名<br>文件名.html]`
- 已存在页面正常显示，待补充页面标注 `❌`
- 用 `-->` 表示跳转关系

### 评审模式与标准模式的差异

| 维度 | 标准模式 | 评审模式 |
|------|----------|----------|
| 目标 | 生成开发用PRD | 评审准备用文档 |
| 组织 | 按模块3段 | 按5步建模 |
| 页面 | 不单独列页面清单 | 页面清单+状态标记+占位 |
| ER图 | 不强制 | 必选 |
| 缺失处理 | 不涉及 | 占位+标记 |
| 输入 | 需业务逻辑清单 | 可从源码/评审议题提取 |

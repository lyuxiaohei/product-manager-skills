## 模式选择

根据用户意图自动选择模式：

| 模式 | 触发条件 | 输出结构 |
|------|----------|----------|
| **标准模式** | 常规PRD生成、版本迭代 | 模块级 3 段（用例→流程→数据） |
| **评审模式** | 用户提到"评审"、"review"、"业务建模"、或列出多条评审议题 | 4 步业务建模（页面→用例→流程→ER），AC紧邻UC，异常并入流程 |

两种模式共享同一套 UC-AC 编号体系和字段说明表规范。

## 使用时机与联动（V2.0 契约，2026-10-11 定稿）

- **使用时点（两条，不论修订由谁驱动）**：
  1. **首次生成原型后**（PDM.Preparation-Prototype 产出落盘）——生成**首版 PRD**；
  2. **每次修订原型后**（PDM.Refinement-Prototype 修订落盘）——**随即使用本技能增量更新**；修订的驱动来源不限：业务沟通意见／彩排人判未过／AI三视角评审需修改，**三个环通用**。因此业务沟通**之前**（每轮修订＋PRD 同步＋彩排通过后）与**期间**（沟通意见→修订→PRD 同步→再沟通的循环中）PRD 都随修订持续生成——修订落盘后的下一步永远是本技能，更新完按所处阶段分流：业务沟通期→彩排→下一轮沟通，AI评审期→再交三视角评审（Review-Summary 收拢）。
- **联动粒度＝主流程锚定增量**：
  - 业务主流程图.html 变更 → PRD 对应章节（业务流程／用例）做**增量更新**；
  - 页面级细节变更（字段／校验／文案／样式）→ 只更新功能清单／字段表；
  - 每次更新在 PRD 头部版本注释记**联动来源**（如「随原型 V1.3.0 同步」）。
- **独立编号**：PRD 与原型各自独立编号、不绑定跳号（版本规则见 VERSIONING.md §8）。
- 联动输入＝原型根 README-修订记录.md 的变更履历（版本／日期／变更摘要／触发来源），按变更摘要定位受影响章节。
- **链路图表示（2026-10-11 分环拍板，2026-10-14 对齐三环版）**：本技能在主流程图上按环分立为同名节点——首版（第1次业务沟通环）／会后同步（第2~N次业务沟通环）／开发期同步（AI评审环）三处，修订原型同理按环两处；循环不跨环节点共用，环内迭代复用本环节点。

## 执行流程

### 阶段一：材料收集与分析（用户确认后进入阶段二）

1. **读取原材料** — 按 `rules/material-checklist.md` 顺序：业务逻辑清单 → 导航索引 → 现有PRD → 源码。**无业务逻辑清单时，直接从源码（HTML/JS原型）提取业务信息。**
2. **确定范围 + 识别模块** — 从材料中提取范围，归类到模块并分配**代号**（Product→P，Order→O）
3. **识别增量变更** — 对比现有PRD，标注模块为新增/变更/未变更（仅增量版本需要）
4. **制定撰写计划** — 按 `rules/structure-rules.md` 确定模块编排顺序，提交用户审阅

### 阶段二：生成PRD（每段写完提交用户审阅）

#### 标准模式（模块级 3 段）

5. **生成版本级** — 范围边界（In/Out Scope，含代号列）+ 角色列表（含代号列）
6. **按模块生成 3 段**（使用 `templates/prd-module-section.md`）：
   - 二.{代号}.2 功能用例与验收（UC + AC 强绑定，**首个模块输出测试账号**）
   - 三.{代号} 核心流程（Mermaid 主流程 + 状态流转含守卫条件 + 异常与边界含非功能）
   - 四.{代号} 数据流向（CRUD 矩阵 + 8列字段说明，**统计口径作为字段行**）
7. **生成可选章节** — 单据流转（有核心实体时）、接口时序（跨系统时）、实时通信（有 WebSocket 推送时）

#### 评审模式（4 步业务建模）

5. **生成版本级** — 范围边界 + 评审议题列表 + 角色列表（一.1）
6. **按 4 步生成**（使用 `templates/version-prd.md` 评审模式骨架）：
   - 二、页面清单 — 含 ✅/❌ 状态标记 + 跳转关系图 + 待补充页面占位
   - 三、业务场景（用例图）— 每模块 UC 用例表 + AC 紧邻（Given-When-Then）
   - 四、业务流程（流程图）— 每模块 Mermaid 流程图 + 异常与边界
   - 五、实体关系建模（ER图）— Mermaid ER 图 + 字段说明表（标粗新增字段）
7. **可选章节** — 状态机（Mermaid 状态图 + 状态流转表），评审涉及状态变更时生成

8. **质量检查 + 合并输出** — 执行 3 项检查，输出到 `PRD/PRD-{项目名}-V{版本}.md`

| 参数 | 说明 | 必填 |

| 上一版PRD路径 | 增量版本时提供 | 否 |

## 输出规范

### 输出文件

- 目录：项目根目录 `PRD/`（不存在自动创建）
- 命名：`PRD-{项目模块名}-V{版本号}.md`
- 骨架：`templates/version-prd.md`（标准模式 + 评审模式）；模块章节：`templates/prd-module-section.md`

### 版本行与联动来源（V2.0 起，规则见 VERSIONING.md §8）

- PRD 头部带版本注释行（md 引用块）：`> V1.0.0｜2026-10-11｜首次生成（随原型 V1.0.0）`
- 联动模式下每次增量更新同轮递增 PRD 版本，并在头部版本注释记**联动来源**（如「随原型 V1.3.0 同步」）
- PRD 与原型各自独立编号，不绑定跳号

### 质量检查项（3 项）

| 检查项 | 说明 |
|--------|------|
| **编号** | 标题编号连续无跳号；UC/AC/模块代号全局唯一不跨模块冲突 |
| **追溯** | UC↔AC「对应用例」列完整，每条验收可追溯到具体用例 |
| **范围** | In Scope 的每个模块都有对应内容；测试账号全文仅出现一次；评审模式页面清单覆盖所有评审议题 |

### 章节结构

#### 标准模式

```
一、范围边界          [必选]
二.1 角色列表         [必选]
二~四 模块3段         [必选，按用户操作路径排序]
  二.{代号}.2 功能用例与验收
  三.{代号} 核心流程
  四.{代号} 数据流向
{N}、单据流转         [可选 · 有核心实体时]
{N+1}、接口时序       [可选 · 跨系统时]
{N+2}、实时通信       [可选 · 有实时推送时]
```

#### 评审模式

```
一、范围边界          [必选，含评审议题]
一.1 角色列表         [必选]
二、页面清单          [必选，含✅/❌状态标记 + 跳转图 + 占位骨架]
三、业务场景          [必选]
  三.1~N 每模块 UC 表 + AC 紧邻
四、业务流程          [必选]
  四.1~N 每模块 Mermaid 流程图
  四.5 异常与边界
五、实体关系          [必选，ER图 + 字段说明表]
六、状态机            [可选 · 评审涉及状态变更时]
```

## Anti-patterns

| 反模式 | 正确做法 |
|--------|----------|
| 臆测未实现的流程 | 每条用例/规则在源码有对应 |
| 验收标准不绑用例 | 每条 AC 填「对应用例」列，绑定到 UC |
| 统计口径单列章节 | 作为字段行写入字段说明表，来源列填公式 |
| 测试账号每模块重复 | 全文仅首个模块输出，其余引用 |
| 非功能需求单列章节 | 并入「异常与边界」非功能子表 |
| 忽略清单的角色泳道图 | 映射到「二.1 角色列表」 |
| 忽略清单的边界条件 | 映射到「异常与边界」非功能子表 |
| diagram-design 可用却用 Mermaid | 优先 diagram-design，Mermaid 仅备选 |
| 忽略清单的单据流转/系统时序/推送链路 | 有核心实体/跨系统/实时推送时生成可选章节（含实时通信） |
| 字段校验在多处重复 | 只写在字段表「校验规则」列 |
| **评审模式：对缺失页面硬编造内容** | 标注 ❌ + 【请补充】，仅写已知信息，留占位骨架 |
| **评审模式：页面清单无状态标记** | 每个页面标注 ✅已有原型 或 ❌待补充 |
| **评审模式：ER图遗漏新增字段** | 新增字段用 **粗体** 标记，字段说明表同步标注 |
| **联动时整篇重写 PRD** | 主流程变更只做对应章节（业务流程/用例）增量更新；页面级细节只更新功能清单/字段表 |
| **联动更新不留来源** | PRD 头部版本注释记联动来源（如「随原型 V1.3.0 同步」） |

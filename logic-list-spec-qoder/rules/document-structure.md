# 文档结构规则 V1.0

定义业务逻辑清单的章节编排规则：标题层级、编号规则、表格结构、全局章节。

---

## 章节结构总览

```
业务逻辑清单 V{版本号}
├── 文档标题 + 版本概述（引用块）
├── 一、{模块名} `V{版本号}`
│   ├── 1.1 {页面名}（filename.html）
│   │   ├── 截图
│   │   ├── 1.1.1 功能用例表       [必选]
│   │   ├── 1.1.2 关键字段数据来源   [必选]
│   │   └── 1.1.3 业务逻辑增强       [可选]
│   └── 1.2 {关系表/跳转表}         [按需]
├── 二、{模块名} `V{版本号}`
│   └── ...
├── {N}、页面导航 `V{版本号}`       [必选]
│   ├── {N}.1 跳转关系
│   ├── {N}.2 返回导航
│   └── {N}.3 登录拦截
└── {N+1}、状态流转 `V{版本号}`     [可选]
```

## 标题层级规则

### 一级标题 `#` — 文档标题

每个文档仅一个，格式：`# {项目名} - 业务逻辑清单 V{版本号}（{版本描述}）`

示例：
```
# 苏银豆商城 - 业务逻辑清单 V0.3（下单与评价流程）
```

### 二级标题 `##` — 模块章节

使用中文数字序号，格式：`## {中文数字}、{模块名} \`V{版本号}\``

示例：
```
## 一、商品详情 `V0.3`
## 二、购物车 `V0.3`
## 三、下单与支付 `V0.3`
```

规则：
- 每个二级标题后用 `---` 分隔
- 按用户操作路径排序（浏览→加购→下单→支付→订单→评价）

### 三级标题 `###` — 页面小节

使用阿拉伯数字编号，格式：`### {X}.{Y} {页面名}（{filename.html}）`

示例：
```
### 1.1 商品详情页（product_detail.html）
### 3.1 确认订单（order.html）
```

### 四级标题 `####` — 子小节

使用三级编号，格式：`#### {X}.{Y}.{Z} {表格类型名}`

固定编号含义：
- `.1` = 功能用例表
- `.2` = 关键字段数据来源
- `.3` = 业务逻辑增强

示例：
```
#### 1.1.1 功能用例表
#### 1.1.2 关键字段数据来源
#### 1.1.3 业务逻辑增强
```

## 版本概述

文档开头使用引用块 `>` 写版本概述，包含：

| 内容 | 说明 |
|------|------|
| 版本范围 | 本次覆盖哪些模块和页面 |
| 页面数量 | 涉及的页面总数 |
| 数据来源说明 | 商品数据、用户数据等来源定义 |
| 统计口径 | 销量、好评率、折扣等指标的计算公式 |
| 测试说明 | 如 `Auth.resetAccounts()` 重置提示 |

## 三表结构

### 功能用例表（必选）

每个页面必须有。

```markdown
| # | 场景 | 操作 | 预期结果 |
|---|------|------|----------|
| 1 | ... | ... | ... |
```

列定义：
- **#**：页内顺序编号，每个表从 1 开始
- **场景**：简短名词短语（2-6字），描述在什么情境下
- **操作**：用户的具体动作，包含元素名称
- **预期结果**：具体到文案、颜色（附十六进制值）、动画、跳转目标（附页面文件名）

### 关键字段数据来源（必选）

每个页面必须有。

```markdown
| 字段 | 数据来源 |
|------|----------|
| ... | ... |
```

列定义：
- **字段**：字段名称，含括号列举子字段（如 `商品信息（图片/名称/规格/价格）`）
- **数据来源**：数据提供方，常见来源：
  - `品牌商城后台商品管理`
  - `品牌商城后台订单系统`
  - `品牌商城后台评价系统`
  - `品牌商城后台积分系统`
  - `品牌商城后台物流系统`
  - `品牌商城后台运营配置`
  - `前端实时计算`
  - `用户操作`
  - `上一页面传入`

**不确定的数据来源**：留白并附建议答案，格式：
```
品牌商城后台{具体模块}（建议：品牌商城后台商品管理 — SKU规格属性）
```

### 业务逻辑增强（可选）

仅在存在跨页面或需要业务确认的逻辑问题时生成。

```markdown
| # | 问题 | 确认结果 |
|---|------|----------|
| 1 | ... | ... |
```

列定义：
- **#**：页内顺序编号
- **问题**：以问号结尾的业务逻辑疑问
- **确认结果**：已确认的回答；未确认的留空并附建议

**不确定的业务问题**：确认结果列留白并附建议答案，格式：
```
（建议：{建议的确认结果}）
```

## 全局章节

### 跳转关系

```markdown
| # | 页面A | 触发条件 | 页面B |
|---|-------|----------|-------|
| 1 | 购物车 | 点击"结算" | 确认订单 |
```

覆盖版本范围内所有页面的跳转关系，编号全局递增。

### 返回导航

一行说明：
```
所有子页面返回按钮统一使用 `history.back()` 返回来源页面。
```

### 登录拦截

```markdown
| 类型 | 页面 |
|------|------|
| 受保护 | 确认订单、订单支付、我的订单、订单详情 |
| 公开 | 购物车、支付成功、物流追踪、评价中心、发表评价 |
```

后附引用块说明注意事项。

### 状态流转（可选）

仅当涉及状态机（如订单状态）时生成。

```markdown
| 当前状态 | 可执行操作 | 目标状态 |
|----------|-----------|----------|
| 待付款 | 取消订单 | 已取消 |
| 待付款 | 去支付 | 待发货 |
```

## 编号连续性要求

1. H2 中文数字不跳号：一、二、三、四、五、六、七
2. H3 在同一 H2 下不跳号：1.1、1.2、1.3
3. H4 在同一 H3 下不跳号：1.1.1、1.1.2、1.1.3
4. 功能用例表和业务逻辑增强表内 `#` 列不跳号
5. 跳转关系表 `#` 列全局递增不跳号

---

## 模块编排顺序

按**用户操作路径**排序：

1. **商品浏览** — 商品详情（浏览起点）
2. **购物车** — 购物车管理
3. **下单与支付** — 确认订单、支付、支付成功
4. **订单管理** — 订单列表、订单详情、物流追踪
5. **评价管理** — 评价中心、发表评价、商品评价、我的评价
6. **页面导航** — 跳转关系、返回导航、登录拦截
7. **状态流转** — 订单状态机（可选）

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 按文件名字母排序 | 按用户操作路径排序 |
| 所有页面都有业务逻辑增强表 | 仅在有需要确认的业务问题时生成 |
| H4 不带编号 | 所有 H4 必须带 X.Y.Z 编号 |
| 截图使用绝对路径 | 使用相对路径 `./screenshots/xxx.png` |
| 跳转表仅列部分跳转 | 必须覆盖版本范围内所有页面的全部跳转 |

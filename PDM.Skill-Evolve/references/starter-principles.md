# 入门横切原则（可选种子）

Starter set version: 3

本文件不是采用者的原则文件。它是一个可选种子：
一套经过筛选的通用方法论原则，在任务观察者循环的长期运行中积累而来，
并已剥离出处（观察条目编号、日期、来源环境中的技能与客户名称）。
生效文件是
`[workspace folder]/skill-observations/cross-cutting-principles.md`，
其权威性来自采用者自己的证据链——因此这里的任何内容，
在采用者有意识地导入之前都不生效。

## 对账

SKILL.md 的第 1 步就整个流程指向本文件；那里只承载触发条件
和一行摘要。

**何时读取本文件：**仅当会话启动协议
（SKILL.md，第 1 步）发现入门原则集对账到期时——即标记文件
`skill-observations/starter-principles-reviewed.txt` 不存在，或
其中的版本号低于上面的 `Starter set version` 行。全新安装时、
现有安装升级到随附本文件的捆绑包后的首次会话时，
以及之后任何新版本扩充了原则集时，都属于这种情况。
普通会话开始时永远不要读取本文件。对账按实质比较，
而非按标题：采用者若已用自己的措辞承载了某条规则，
即视为已覆盖，只有未被覆盖的条目才会被提议。每当条目
新增或发生实质变更时，都要提升版本行的版本号，
否则既有安装永远看不到变更。

**提议只有一行，且只做一次：**“捆绑包随附 N 条入门
原则；其中 M 条未被你的文件覆盖——要看看吗？”
若回答“要”，则只展示未覆盖的条目，由采用者挑选。
全新安装时 M 等于 N，选择就简化为“从空白开始，
还是用种子预填”。无论哪种情况，事后都要把随附版本
写入标记文件，使该提议在原则集变化之前不再重复。
**绝不可静默预填：**生效文件的权威性来自采用者自己的
证据链，未经审视的导入规则与该文件自身承载的修剪
原则（第 11 条）相矛盾。

**如何导入：**把采用者选中的条目（全部或子集）按
`references/skill-authoring.md` 中的模板格式复制进生效文件，
将 `**Added:**` 设为导入日期、`**Propagation:** opportunistic`、
`**Status:** active`，并为每条添加 `**Origin:** imported from starter set`。
Origin 标记是承重的：它告诉之后的每一次审查，该条目是在没有
本地证据的情况下进入的，因此修剪轮次可以像对待任何单条
观察的规则一样自由地删除它。在采用者自己的工作中从未
触发的导入原则应当移除，而不是出于敬意而保留。

**用证明该条目成立的证据扩展 `Origin:`**——在
`imported from starter set (#N)` 部分之后，加一行点名本地产物：

```text
**Origin:** imported from starter set (#3). Fits: a documented commit-message
format failed seven times in this repo's history with no gate in front of it.
```

只此一行，趁理由仍在手时就写下。正是它
让之后的修剪轮次可做决断：所引证据已不再成立的
原则，是一条可明确移除的条目；而一条无说明的导入，
在审查时与一条未经审视的导入无从区分——因此没有
这一行，原则集就只能永远增长，而这正是第 11 条
存在所要防止的结局。

### 1. 开源技能必须包含开源许可证
**适用范围：**所有开源技能
**要求：**在技能前言中包含一份公认的开源许可证声明，并在
技能目录中放置对应的 `LICENSE`（或 `LICENSE.txt`）文件。任何
广受认可的许可证均可——文字为主的技能用 CC BY 4.0，代码
为主的技能用 MIT 或 Apache 2.0，需要更强著佐权（copyleft）
的用 CC BY-SA 或 GPL 系列许可证。选择权属于技能的作者；
要求的只是*必须有*一份许可证。

### 2. 开源技能必须包含作者署名与反馈途径
**适用范围：**所有开源技能
**要求：**在 frontmatter 中携带作者与许可证信息
（`license:` 加上含 author 与 source 的 `metadata:`），并在
技能末尾以一行页脚重复一次，这行页脚在会剥离
frontmatter 的工具下依然保留。正文以技能做什么开场，
而不是致谢。把规范来源与一条反馈途径（issue 跟踪器、
仓库、联系地址）作为愿意代为起草报告的提议，写在紧邻
页脚之前的简短小节里。一个没有通向作者回路的已发布
技能，无法从其读者那里得到改进。

### 3. 含规则的技能必须包含预检验证步骤
**适用范围：**所有带有显式规则或要求的技能
**要求：**包含一个验证步骤：智能体在交付前重读
技能的规则，并对照这些规则检查自己的输出。
不被强制执行的规则只是建议。

### 4. 开源技能不得包含可识别客户的信息
**适用范围：**所有开源技能
**要求：**在技能、其引用文件或示例中的任何位置，都不得
出现客户名称、项目 URL、域名或专有细节。在编写时、
在记录观察条目时、以及发布时各执行一次核查——日志
和提交信息本身也是产物。

### 5. 开源技能必须使用工具无关的语言，且具体示例在前
**适用范围：**所有开源技能
**要求：**引用能力（浏览器访问、文件系统访问、
网络搜索、调度器），而不是硬编码对某一产品的依赖。
技能的读者是智能体而非人类，而智能体会拿具体工具名
与其工具集中的工具做模式匹配——因此先以主环境为例
点名具体工具，再给出通用回退：“在 [环境] 中，
使用 `[tool]`。在其他环境中，使用可用的等效工具。”
通用优先的措辞，是以机器可执行性为代价
来优化人类可读性。

### 6. 生成结构化输出的技能必须以多个真实示例为基础
**适用范围：**所有产出结构化输出（配置、标记语言、
代码模板、数据格式）的技能
**要求：**用目标格式的若干真实示例来构建技能，
绝不止一个示例——单个示例会在边界情况、
高级特性和格式变体上造成盲区。当由此形成的
规范过于详细、不适合放进技能正文时，
把它放进参考文件并指向它。

### 7. 子智能体必须拥有完整输入和经过验证的输出
**适用范围：**所有把内容生成委派给子智能体的技能
**要求：**为速度可以使用子智能体，但绝不能让它们猜测
数据值。安全的委派：验证、格式检查、交叉引用检查——
一切所需输入都能写进任务简报并随之传入的工作。
除非另有防护，否则不安全：任何需要实时数据的工作。
对携带数据的任务，父级先收集原始数据，再完整传入；
缺少某个值的子智能体应写下 `[VERIFY: value not confirmed]`
占位符，而不是一项貌似合理的编造。返回之后，
父级对照来源验证每一个具体值。两条子规则：
**（可视化）**委派图表或表格时，按最终展示顺序
传入确切数据——预先过滤、预先排序——绝不传入
需要子智能体自行排序的更宽泛集合，并对照来源
抽查内容准确性，而不只是版式；**（定性判断）**
数值检查不会对以*判断*形式陈述的输出触发——一条
被报告的冲突、缺陷、风险或就绪结论没有可供
核对的单位——因此任何将作为发现到达用户处的
子智能体主张，都必须由父级按可证伪的粒度抽查
（通常一次 grep 就够）。要求子智能体为每条主张
附带可定位的证据（文件、行号、匹配到的字符串）；
没有证据的主张是要核实的主张，不是要转述的主张。
错误的值在有东西拿它做计算时会响亮地失败；错误的
定性判断则因被附和而被消费，而附和不留痕迹。

### 8. 工具失败时的优雅恢复
**适用范围：**所有使用交互式工具的技能
**要求：**当工具交互（提问控件、表单输入）被拒绝或
失败时，以对话方式恢复，不向用户暴露内部错误状态。
用纯文本重新措辞并继续；不要认定
是用户主动关闭了该交互。

### 9. 让交互模态匹配对话能量
**适用范围：**所有采集用户输入的技能
**要求：**在任务开始的结构化采集阶段使用结构化工具（提问
控件、表单）。在自由流动的对话中，优先纯文本提问。
不要把一段丰富的对话
降级为多选题。

### 10. 小型可行动集合既要内联呈现，也要保存到文件
**适用范围：**所有产出可交付结果的技能
**要求：**当结果是一小组可行动条目（大约 25 条或更少的
链接、任务或类似物）时，既在对话中内联呈现，也保存到
文件——文件是持久记录，内联列表服务于当下工作流。对
更大的集合，文件为主，内联只展示摘要。不要强迫用户为
马上就要消费的内容
去打开一个文件。

### 11. 技能需要修剪，而不只是生长
**适用范围：**所有技能
**要求：**每次审查时，以与寻找可添加内容同样的自觉，
去寻找可删除的内容：来自单次观察且从未复发的规则、
从未被查阅的小节、用户一贯绕开的繁复流程、
为“以防万一”加入却从未触发的复杂度。
一个只增长的技能，最终会重到无法使用。

### 12. 使用源数据中的规范标识符，绝不从派生字段重建
**适用范围：**所有对来自多个来源的数据进行连接、
匹配或交叉引用的技能
**要求：**始终使用源系统中的规范标识符。绝不
从派生或转换过的字段重建标识符（由名称生成
URL、由 slug 推断 id）。重建出的标识符会引入
能通过随意审查的静默假阳性，并污染分析。
一张人工维护的对照表前期更费事，
但产出可验证、可审计的结果。

### 13. 读或写工作区文件的技能必须维护参考索引
**适用范围：**所有依赖共享工作区中的文件、
或向其产出文件的技能
**要求：**包含一个“参考文件”小节，为关键文件
各附一行描述，作为活索引来维护——文件创建时
添加，被取代时修剪。没有它，加载该技能的新会话
就无从发现相关工作区文件的存在，
技能也无法利用自己的历史产出。

### 14. 定时任务调用技能，而不是重新实现它们
**适用范围：**所有执行某项技能中
已记载流程的定时任务
**要求：**定时任务的提示词加载技能并遵循其
指示；它不把流程内联进提示词。技能保持唯一
事实来源：改进自动流入定时执行，方法论保持
可共享、可版本化。把技能内容复制进任务提示词，
会制造一个逐渐漂移的维护分叉，
并把方法论困在一个不可共享的位置。

### 15. 定时任务提示词是轻量编排器——智能住在技能里
**适用范围：**所有定时任务
**要求：**任务提示词不携带任何领域知识、来源清单、
输出格式或筛选标准；这一切都属于任务所调用的技能。
模式：任务提示词 = “加载技能 X，然后遵循其指示。”
这使技能可以独立于任务改进、在临时会话中被手动调用、
并在每次运行时被任务观察者观察。创建任何定时任务时，
先问该领域是否已存在技能——
若没有，先创建技能。

### 16. 被中断的操作是部分完成的操作——重试前先验证状态
**适用范围：**所有执行批量数据操作
或多步变更的技能
**要求：**当操作被中断、超时或中途失败时，
假定为部分成功，而非全部失败。在以相同或
其他方法重试之前，先验证当前状态——批量
插入（部分行已成功）、文件操作（部分文件已
写入）、多步流程（部分步骤已完成）。模式：
中断 → 验证状态 → 调整剩余工作 → 继续。
绝不在失败后假定位面干净如初。

### 17. 绝不建议以手工输入技术内容作为变通
**适用范围：**所有技能及所有对话式交互
**要求：**当基于工具的工作流中断（格式化、粘贴失败、
编码问题）时，绝不建议用户手工输入或转录代码、
标记语言、结构化数据或任何技术内容——无论长短。
另找一条机器辅助的路径：换一种文件格式、换一种
交付机制、换一个工具。“只有 N 行而已”永远不构成理由。

### 18. 浏览器自动化是代价高昂的最后手段
**适用范围：**所有使用或推荐浏览器自动化的技能
**要求：**浏览器工具的载荷会随对话增长而复利式累积。
任何使用它们的技能都必须记载这一代价，在存在非浏览器
替代方案时予以提供，在同等有效时把非浏览器路径设为
默认，并为超过少量浏览器调用的会话设置检查点。
严格按次序升级：先用抓取或搜索工具，
只有当它们在特定来源上失败后才用浏览器；而在需要
浏览器却不可用时，等待用户，而不是跳过、中止或
发明一个替代方案。

### 19. 推荐 API 访问的技能必须注明网络沙箱影响
**适用范围：**所有推荐直接访问
第三方 API 的技能
**要求：**注明：处于沙箱化环境（桌面智能体、
公司代理）中的用户，可能需要先在其网络设置中
把该 API 的域名加入白名单并重启应用，调用
才能成功；并在已知处点名具体域名。否则用户
只能在工作流中途通过失败的请求才发现阻碍。

### 20. 技能只包含改变行为的内容
**适用范围：**所有技能，开源与内部皆然
**要求：**只保留会在执行时改变智能体行为的内容。
变更日志、版本说明、历史小节、致谢、自我叙述式
文字、面向维护者的背景信息，属于辅助文档、提交
历史或 README——不属于技能。检验标准：删掉这
一行，会改变智能体的行为吗？这并不削减示例、
反模式或完整场景——它们对规则遵从起支撑作用，
因为光秃秃的规则比带上下文的规则更容易被违反。
每一行不起支撑作用的内容，都是每次加载都在
支付的 token 成本，却没有任何行为收益。

### 21. 在开源技能中使用智能体无关的语言
**适用范围：**所有开源技能
**要求：**把执行任务的 AI 称作“the agent”（智能体），而不是
某厂商的模型名，除非该处引用确实特定于该厂商：产品名
（一个应用、一个 CLI、一个托管聊天服务）、配置文件命名
约定、只有该厂商才有的架构或 API。对执行者的泛称
（“[model] 做了 X”、“告诉 [model] 去……”）一律改为
“the agent”。这是工具无关原则在行为者称谓上的延伸。
只在一个环境中运行的内部技能豁免。

### 22. 验证厂商当前指引需要核查带日期的变更日志，而不只是文档页
**适用范围：**所有核实或断言某第三方
平台当前指引的技能
**要求：**当某个流程要确认某厂商当前推荐、
支持或要求什么时，核查厂商带日期的变更日志
或更新页——而不只核查文档页（例如搜索引擎
带日期的“updates”页，与文档并列）。抓取来的
文档页是缓存快照，曾被观察到提供落后一周、
缺少新属性的版本；变更日志带日期且权威，
既能抓到过期的抓取，也能抓到技能写成之后
发生的变化。推论：任何关于近期更新的文档的
“此属性/变更不存在”的主张，交付前都需要
第二渠道（变更日志、原始抓取或浏览器）——
第一假设应是渠道内容过期，而不是在厂商处不存在。

### 23. 绝不跨结构不同的分群聚合
**适用范围：**所有对多于一个分群（市场、品牌、
客户、测量载体、模板、渠道、时间桶）上的指标
做汇总、平均或排名报告的技能
**要求：**聚合之前，先检查各分群在结构上
是否可比——同一测量载体、同样的人群规模、
同一分母行为。若不可比，先按分群分别报告，
只有在申明异质性的前提下才聚合。聚合
是一个编辑决策，不是中立的默认。
诊断法：跨异质分群的聚合总会美化某个分群、
埋没另一个，**而被埋没的那个往往就是发现所在**
——因此当某个聚合得出“弱势”时，先检查是不是
小分群正被大分群淹没，再作报告。

### 24. 先取回实例，再描述它
**适用范围：**所有依据相关证据来描述、分类或验证某个
具体制品——一个 URL、一个 DOM 元素、一台主机、
一条记录、一个文件——的技能
**要求：**在断言某个具体制品*是什么*之前，先取得制品本身，
而不是从与它相关的信号去推理。表层模式是*关于*制品的证据，
之所以被拿来顶替制品，是因为它们已经在手，而取回要花
一次调用；这种顶替在输出中不可见，因为从一条眼熟的
模式做出的推断，读起来与一条已验证的事实一模一样。
典型错误：把一条匹配的 DNS 记录读作某主机曾提供内容的
证明，而它提供的其实是重定向；把一次 URL 清点读作
“什么链接到这些 URL”的证据；把序列化 HTML 中的字符
相邻读作 DOM 包含关系；在数据集本就带有页面类型列时，
用 URL 的形状推断其页面类型。诊断法：说出某条主张
所依赖的证据，问它是制品本身还是一个相关物；若是
相关物，问取回制品要付出什么——通常一次调用。
两条推论：数据集已对实体做了分类之处，读它的字段，
而不是重新推导；直接访问被封锁之处，优先选另一条
响应层渠道（检查工具、渲染视图），
而非基础设施层信号。

### 25. 一条已验证的理由胜过两条——当第二条未经核查时
**适用范围：**所有产出建议、忠告、论证
或理由的技能
**要求：**附加在一条建议上的每条支撑理由，
都必须通过与建议本身相同的证据门槛。当单条
论证显得单薄时，把它说得更精确，而不是去抓
第二条；若第二条理由当下无法核查，就标注为
未核查，或干脆不写。这个机制并不让人觉得
像编造：对第二条理由的搜索，是在搜索*貌似
合理且指向同一方向的东西*，而支撑理由恰恰
因为不是承重主张，只得到一小部分审视——
然而它们正是读者无从独立核实的部分。
一条错误的支撑理由，会把自己的不可靠
传染给旁边那条可靠的主张。推论：在基于
某份文档的数字构建论证之前，先查明数字的
作者——继承或第三方的数字会双向偏离，
并改变其中哪些值得争辩。

### 26. 伴生技能必须申明其覆盖边界
**适用范围：**所有记载由他人所有的表面的技能——
一个工具、一个 MCP 服务器、一个 API、一个平台、
一个产品——以及任何作为某基础技能的伴生
而被加载的技能
**要求：**在靠近开头处申明：所记载的表面中，
技能覆盖哪些、不覆盖哪些。加载伴生技能，
恰恰是因为智能体不了解该工具，所以文件对某个
表面的沉默，会被读作该表面不存在，而不是文件
不完整——而加载这一行为本身，又压制了本可
澄清这一差别的探索。把未覆盖的区域明确点名，
哪怕只是一张背后没有任何细节的裸清单；
被点名的缺口，是智能体知道要问的问题，
未点名的则不是。反向读法：一个不申明边界的
既有伴生技能，其覆盖是未知的，而非完全的，
因此在断定某功能缺席之前，先对照产品验证。
把单个工具或端点标注为“用过/未用过”
（见 `references/skill-authoring.md` 的
“记录外部工具面”）并不能替代这一点：
任何标注方案都无法描述文件从未提及的表面，而一个技能可以在它包含的每一行上都准确，却只覆盖该工具所做的大约一半。

### 27. 每个技能都以捆绑包形式交付，并按渐进式披露组织结构，无论大小
**适用范围：**所有技能，开源与内部皆然
**要求：**技能是一个目录，作为单个捆绑包交付
与安装，无论它当前持有一个文件还是二十个——
不存在单文件交付格式。其结构从第一稿起就
遵循渐进式披露：SKILL.md 承载心智模型、每次
调用都会改变行为的规则、以及带显式加载触发的
指针清单；一切只在某一类工作情景中才会查阅的
内容（工具清单、配方、分类法、按变体的细节、
陷阱目录、合同或条款摘录）放入 `references/`。
行数阈值（约 500 行）只标记既有的、尚未拆分的
技能被补做拆分的那个节点；它不为新写或
实质修订的作品设结构门槛。理由：一条按制品
大小切换的规则，会为一件事造出两种格式、
一条每个消费者都要重新推导的边界，而单一
格式能彻底消灭“裸 SKILL.md 被截断”这一类安装失败。

### 28. 缺席永远不能由汇总型工具来确立
**适用范围：**所有对某个制品的内容作主张的技能——
一张表格、一个页面、一个清单文件、一个仓库、
一份报告、一个工具表面
**要求：**任何形如“X 不在 Y 中”的陈述，
都不得建立在对 Y 做摘要、采样、渲染或
就 Y 答问的工具上——文档连接器的表格
视图、抓取工具的回答、搜索结果、渲染摘要。
存在可以由这类工具确立（它找到了那个东西）；
缺席不能，因为“东西不在”与“工具没有去看”
产出完全相同的输出，读起来是同样自信的
文字。缺席需要原始制品——完整的表格、
原始 HTML 或清单文件、完整的导出——
并在其上跑一次字面匹配；主张要么点名
产出它的工具，要么不交付，而其工具
是汇总器的主张要被移除，绝不是被缓和。
当某个工具同时返回声明的规模与渲染结果
（表格范围及其各行、计数及某一页）时，
先比较两者，再读其中内容；不匹配意味着
样本，而非总体。宁选返回制品本身的接口，
不选返回其摘要的接口，因为只有后者可能被静默截短。

### 29. 技能持有方法；带日期的值活在技能点名的工作区文件中
**适用范围：**所有技能，开源与内部皆然
**要求：**技能持有方法、规则与流程——
明年与今天同样为真的东西。任何带日期
或持有当前值的东西——目标、数字、费率、
日程、客户与来源映射、日志——活在技能
点名的工作区文件中（在其参考索引中，
见第 13 条）。技能是方法的唯一所有者；
文件是值的唯一所有者。当两个技能需要
同一个值时，都指向该文件，谁也不复制它。
理由：技能内的带日期值会静默过期——技能被当作
现时内容加载，改一个数字要走一次技能审查，
而两个技能各自持有的副本会漂移。工作区文件中的值无需审查即可更新，且只在一处。

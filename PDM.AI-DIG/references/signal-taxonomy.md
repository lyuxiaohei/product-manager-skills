## 一、标签总表

| 标签 | 中文名 | 定义 | 置信度 | 主喂维度 | 辅喂维度 |
|------|--------|------|--------|---------|---------|
| `ACTION_DENSE` | 动作动词密集 | 单句/单段内连续 3+ 个人工动作动词 | 中 | 频率+耗时（动作密度=人工密度代理） | 规则存在形态 |
| `PAIN_POINT` | 情绪痛点 | 带情绪色彩的抱怨/疲惫表达 | 中 | ROI 佐证（痛感强度） | 容错度 |
| `SYSTEM_HOP` | 系统切换 | 跨系统/工具的导出-导入-复制动作 | 高 | 数据可得性（断点=数据不通） | 频率+耗时 |
| `WAITING_BLOCK` | 等待阻塞 | 等他人/他部门处理 + 主动催促 | 高 | 频率 | 技术路线提示（跟单型智能体） |
| `IMPLICIT_RULE` | 隐性规则 | 经验装在人脑子里、无成文规则 | 高 | 规则存在形态（口头/直觉） | 技术路线→LLM 主场 |
| `EXCEPTION_RISK` | 异常故事 | 讲述出错的具体事故 | 高 | 容错度（反向：后果重=低容错） | ROI 量化线索 |
| `LOOKUP_GAP` | 查找缺口 | 为找信息翻记录/问人/翻聊天记录 | 高 | 数据可得性（语料散落） | 技术路线→RAG/知识库 |
| `WISHFUL_THINKING` | 理想化愿望 | "要是能…就好了/一键…" | 中 | 显性需求锚点 | 真伪闸门对象 |

> 置信度指信号来源强度：高=信号本身即证据（动作/断点/事故可直引）；中=词面标记需交叉确认。

## 二、逐类详表（触发词 + 命中示例 + 注意事项）

### ACTION_DENSE 动作动词密集

- 触发词：查 / 填 / 发 / 导 / 复制 / 粘贴 / 核对 / 录 / 转 / 算 / 汇总 / 整理 / 发给 / 贴到 / 抄一份……
- 命中示例（原创方案原例）：「我先查一下，然后填到OA里，再发给财务」
- 判定：单句 3+ 连续动作动词，或一个段落内指向同一业务的动作链
- 注意：动作密集 ≠ 高频——密度是人工参与度信号，频率须从次数表述（"每天/每周都要"）另行确认；仅密度命中且无频次表述时，ROI 按"中"计 `[推断]` 并进待澄清

### PAIN_POINT 情绪痛点

- 触发词：烦 / 最头疼 / 容易漏 / 老是错 / 受不了 / 崩溃 / 坑 / 隐患 / 耽误事 / 离不开人……
- 命中示例（原例）：「这个最烦，特别容易漏」
- 注意：情绪词只作 ROI 与容错的佐证信号，**不单独成节点**——须与动作类信号共现才参与聚类

### SYSTEM_HOP 系统切换

- 触发词：从X导出来 / 复制到Y / 再贴到 / 两边录 / Excel 转 ERP / OA 里再弄一遍 / 重新录一道……
- 命中示例（原例）：「从Excel导出来再复制到ERP里」
- 价值：每次 hop = 确定次数的人工搬运（ROI 分子最扎实的来源）+ 集成断点定位
- 技术路线提示：hop 多因系统间无接口 → 规则引擎/RPA/集成候选；若中间夹人工判断（"看情况决定贴到哪"）则升 LLM 判断节点

### WAITING_BLOCK 等待阻塞

- 触发词：卡在 / 等X那边 / 催 / 天天问 / 追着 / 还没回 / 拖了X天 / 得盯着……
- 命中示例（原例）：「一直卡在法务那边，我得天天催」
- 技术路线提示：等待类节点的 AI 形态 = **通知/催办/状态跟单智能体**（非内容生成）；等待的耗时归"人盯"成本计入 ROI
- 注意：责任方在外部（客户/法务/合作方）时，AI 只能做跟进提醒、不能自动化对方——方案形态标"跟单型"

### IMPLICIT_RULE 隐性规则

- 触发词：老员工 / 老师傅 / 都知道 / 看情况 / 凭经验 / 惯例 / 这么多年 / 心里有数 / 没写下来 / 说不清但有规矩……
- 命中示例（原例）：「反正老员工都知道，就是看情况」
- 价值：**B 级（LLM 辅助）核心判据**——规则装在人脑子里 = 规则引擎做不了 = LLM 要学的语料所在；老师傅在 = 语料源在
- 注意：隐性规则 + 老师傅离职风险 → 升优先级（知识资产化叙事）；无配合意愿/无传承渠道时数据可得性降档

### EXCEPTION_RISK 异常故事

- 触发词：上次 / 有一次 / 出大事 / 搞错了 / 赔了 / 损失 / 返工 / 客户投诉 / 事故 / 用错版本……
- 命中示例（原例）：「上次客户改了三次，我们用了旧版，出大事了」
- 价值：容错度最硬的证据（"赔5000" = 低容错）；异常处置流程本身常是 C 级人机协作节点（AI 预判 + 人处置）
- 注意：单一故事 ≠ 高频——故事给后果证据，频率另判；故事内含金额/时长直接引用作量化依据

### LOOKUP_GAP 查找缺口

- 触发词：翻聊天记录 / 不知道他怎么填的 / 问一圈 / 找不到 / 翻邮件 / 翻台账 / 对不上得问 / 之前谁经手的……
- 命中示例（原例）：「我不知道他上次怎么填的，只能翻聊天记录」
- 价值：**知识库/RAG 机会的定位信号**——语料存在（聊天记录/邮件/台账）但无检索入口
- 技术路线提示：语料在聊天工具 = 导出+向量化路径；数据可得性按"部分"计（语料在但未结构化）

### WISHFUL_THINKING 理想化愿望

- 触发词：要是能 / 一键 / 自动就好了 / 最好能 / 梦想 / 就不用人工了 / 能不能直接……
- 命中示例（原例）：「要是能一键生成这个表就好了」
- 价值：显性需求锚点——客户自己指出的方向，机会敏感度最高
- **真伪闸门**：愿望 ≠ 需求。单独命中（无 ACTION_DENSE / IMPLICIT_RULE / SYSTEM_HOP 等过程信号佐证）→ 标"待验证"，**封顶 C 级 + 强制人审**；有过程信号佐证（愿望指向的环节确实人工密集）→ 按正常四步定级
- 注意：愿望常低估实现成本（"一键"背后多系统打通），方案层必须附成本提示

## 三、信号 → 维度映射与打分规则

| 维度 | 信号来源 | 有数时 | 无数时 |
|------|---------|--------|--------|
| 频率 | ACTION_DENSE 次数表述 / WAITING_BLOCK 催促频次 / SYSTEM_HOP 次数 | 一天X次 / 一月X次，用数 | 高/中/低（按信号密度推断，标 `[推断]`） |
| 耗时 | "每次X分钟/X小时/X人天" 表述 | 用数 | 高/中/低 |
| 规则存在形态 | IMPLICIT_RULE（口头/直觉）/ SOP 提及（文件化） | — | 文件化 / 口头 / 直觉 三态 |
| 数据可得性 | SYSTEM_HOP（断点）/ LOOKUP_GAP（散落语料）/ 系统名提及 | — | 全 / 部分 / 无 |
| 容错度（门槛维度） | EXCEPTION_RISK（后果）/ PAIN_POINT 中"漏/错"表述 | 有金额用金额 | 高 / 中 / 低 / 未知 |

ROI 换算：频率 × 耗时 = 年人力小时（按 365 天/年保守口径估算；一天一次 × 10 分钟 ≈ 年 60 小时；一天一次 × 2 分钟 ≈ 年 12 小时，压线场景建议按客户意向判断）。

## 四、组合规则

1. **多重命中**：节点收全标签；主喂维度按最高置信信号定（高置信标签：SYSTEM_HOP / WAITING_BLOCK / IMPLICIT_RULE / EXCEPTION_RISK / LOOKUP_GAP；中置信：ACTION_DENSE / PAIN_POINT / WISHFUL_THINKING）
2. **黄金组合**：
   - IMPLICIT_RULE + 语料在（LOOKUP_GAP 或聊天记录/邮件提及）→ **B 级强信号**
   - SYSTEM_HOP + 明确规则（"按X标准导"）→ **A 级候选**（RPA/集成）
   - WAITING_BLOCK + 高频催促表述 → **跟单型智能体节点**
   - EXCEPTION_RISK + 处置流程描述 → **C 级人机协作**（AI 预判 + 人处置）
3. **冲突处理**：愿望与故事矛盾（愿望指向消灭的异常仅发生过一次）/ 频次与密度矛盾 → 待澄清清单，不强行定级

## 五、降级与待澄清登记

| 标记 | 场景 | 去向 |
|------|------|------|
| `UNCLEAR_REF` | 模糊代词（那玩意/这边/弄完）无法定位对象 | 待澄清清单 |
| `UNKNOWN_SPEAKER` | 无署名逐字稿分不出说话人 | 待澄清清单 + 该段信号置信降档 |
| 未提及 | 动作输入/输出逐字稿未提及 | 动作记录标"未提及"，禁止补全 |
| 待验证 | WISHFUL 单独命中 / 矛盾信号 | 真伪闸门：封顶 C + 强制人审 |
| `[推断]` | 无数字按信号密度估分 | 显式标注，与原文依据区分 |

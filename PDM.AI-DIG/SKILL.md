# PDM.AI-DIG · AI 切入节点挖掘 v1.1.3

> 定位：**冷启动挖掘器**——不依赖任何前置产出（无预调研报告/竞品矩阵也能跑），从需求调研逐字稿/纪要中挖出 AI 与智能体潜在切入节点。链路内场景（有 PDM.Preparation 报告）优先走 PDM.Preparation-Analysis 产出四，本技能服务冷启动场景与交叉验证。

## 1. 定位与适用场景

回答一个核心问题：**"这段对话里，藏着哪些可以交给 AI/智能体的活？"**

适用：
* 第一通电话、非正式沟通、任意需求分析会的逐字稿/纪要——无预调研前置的冷启动场景
* 产品经理快速评估某次客户沟通中的 AI 切入机会（售前弹药/方案思路/汇报素材）
* 与 PDM.Preparation-Analysis 产出四交叉验证（两套独立扫描结果对照）

不做：
* 完整需求转化（MoSCoW/矩阵映射/原型要素清单 → PDM.Preparation-Analysis）
* 替代客户确认（分级为初判，终判留给客户）
* 编造：无原文依据的动作/字段/系统一律不输出

## 2. 输入约定

| 参数 | 必需 | 说明 |
|------|------|------|
| 逐字稿（优先）/ 会议纪要 | ✅ | md/docx/pdf/html/txt。逐字稿=全信号模式；纪要=降档模式（见 §3①）。**PDM.NOTE-CHECK 净化修订版为最优输入（v1.1.3，含未落盘 v1.1.2 合并）**：名称已归一、头部红旗摘要可预登记待澄清；其"纪要降档模式"可豁免一档（**豁免仅适用于逐字稿净化版＝升回全信号；纪要净化版不升全信号，仍按降档档位，尾注声明"输入为纪要净化版"——名称归一≠信号补回**）；配套 `{会议标识}-核查标签-*.md` 同目录命中时逐行读入——A/全量 B 行预登记进待澄清清单（原文位置列标 NOTE-CHECK 编号），`B*（快检未外核）` 行登记但不进候选节点依据（仅作疑点线索） |
| 背景信息 | 可选 | 客户角色/业务领域/已知系统列表/本次访谈目标。缺失不阻塞，评分按默认口径并在输出中列"未提供" |
| 上游 PDM 报告 | 可选 | 检测到（用户提供或同目录发现 v1.4+ 预调研报告）时进入对齐模式（见 §7） |

输入为扫描版 pdf 时，先经 vinfield-PDF OCR 提文本（临时文件走系统 TEMP 目录），再进入本流程。

运行中信息缺口不阻塞执行（冷启动定位），但逐项登记入待澄清清单。

## 3. 执行流程（五段）

```
输入（逐字稿/纪要 + 可选背景）
  │
  ├─ ①输入解析器 ──分段/说话人/降档判定──→ 结构化文本
  │      ▼
  ├─ ②信号扫描器 ──8类标签全量捞────────→ 命中句清单（对齐模式+①④通道）
  │      ▼
  ├─ ③动作链拆解器 ──动作→动作→动作────→ 动作记录 A-01..n
  │      ▼
  ├─ ④聚类与定级器 ──四步定级顺序────────→ 节点 + A/B/C/D + 人审
  │      ▼
  ├─ ⑤输出格式化器 ──三层输出+评审表─────→ md（内嵌 mermaid）
  │      ▼
  输出：AI切入节点方案-{客户/来源}-{YYYYMMDD}.md
```

### ① 输入解析器

- 逐字稿：分段、时间戳（如有）、说话人区分——**区分不出标 `UNKNOWN_SPEAKER`，不猜**；语气词保留（情绪信号密度所在，不清洗）
- 纪要：**降档模式**——识别四类锚点（困难/瓶颈/系统名称/待确认事项），全节点置信度降一档，输出尾注声明"纪要为加工品，信号密度低于逐字稿"
- 背景信息登记：四项（角色/领域/系统/目标）逐项登记，缺失标"未提供"；已知系统列表用于 SYSTEM_HOP 信号交叉（提及系统名×已知列表）

### ② 信号扫描器

- 逐段扫描，8 类信号标签全量捞，定义+触发词表+维度映射见 `references/signal-taxonomy.md`
- **只捞不判**：扫描器不做价值判断，可疑即登记，防漏（宁多勿漏，评分阶段收敛）
- 每条命中登记：标签 + 原文引用 + 段落位置
- 对齐模式（有上游报告）：并入通道①（M 挂载点回答）与通道④（OP·AI 机会点回答）两路高置信信号

### ③ 动作链拆解器

将命中信号的长段落按"动作 → 动作 → 动作"拆解。规则：

- 每个动作必须有原文依据，**禁止补充材料中未出现的动作**
- 一个叙事段落通常拆出 3~8 个动作
- 模糊代词（"那玩意/这边/弄完"）标 `UNCLEAR_REF` → 待澄清清单
- 输入/输出字段：逐字稿提不出就标"未提及"，禁止补全

动作记录结构（中间态）：

```
动作ID: A-01
原文: 把各个渠道的报表导出来
场景: 每周五报表汇总
输入: 各渠道报表系统（或"未提及"）
输出: 待整合的原始表格（或"未提及"）
命中信号: SYSTEM_HOP + ACTION_DENSE
```

### ④ 聚类与定级器

动作按业务环节聚类成候选节点（节点名=业务动作，如"月度对账""周报表汇总"；编号冷启动模式 DIG-N{序}，对齐模式沿用 AI-N{序}）。**四步定级顺序，强制按序执行，不得跳步**：

1. **ROI 门槛**：频率 × 耗时 = 年人力小时（换算基准：一天一次 × 10 分钟 ≈ 年 60 小时，按 365 天/年保守口径；按 250 工作日/年则约 42 小时）
   - 年 < 10 小时 → 直接落 D（储备），不再往下判
   - 年 10~50 小时 → 继续，但输出标注"ROI 偏低，需客户明确意向"
   - 年 > 50 小时 → 继续
   - 阈值为启发式，可按领域校准；无数字时按信号密度估高/中/低并标 `[推断]`
2. **五维评估**：频率/耗时/规则存在形态/数据可得性/容错度——前四维定分级，容错度只定人审（见 §4）
3. **容错度校正**：只决定人审要求（高=无 / 中=抽样 / 低/未知=强制），**不改分级、不改技术路线**
4. **落级**：A/B/C/D + 标注 ROI 值与依据 + 技术路线 + 人审要求

**真伪闸门（落级前执行）**：`WISHFUL_THINKING` 单独命中（无 ACTION_DENSE/IMPLICIT_RULE 等过程信号佐证）→ 标"待验证"，**封顶 C 级 + 强制人审**；愿望与异常故事矛盾（愿望指向消灭的异常仅发生过一次）→ 待澄清清单。

### ⑤ 输出格式化器

生成标准 md 文档（结构见 §5），内嵌 mermaid 动作链图。v1 只出 md，不做 Excel 导出（留 v2）。

## 4. 评分维度（五维 = 四维加权 + 容错度门槛）与信号映射

| 维度 | 作用 | 取值 | 主要信号来源 |
|------|------|------|-------------|
| 频率 | ROI 分子 | 一天X次/一月X次，或高/中/低 | ACTION_DENSE 次数表述、WAITING_BLOCK 催促频次 |
| 耗时 | ROI 分子 | 每次X分钟/X人时，或高/中/低 | 时长表述、SYSTEM_HOP 搬运量 |
| 规则存在形态 | 技术路线分岔 | **文件化 / 口头 / 直觉** | IMPLICIT_RULE（口头/直觉）、SOP 提及（文件化） |
| 数据可得性 | 技术条件 | 全 / 部分 / 无 | SYSTEM_HOP（断点）、LOOKUP_GAP（散落语料） |
| 容错度 | **门槛维度（不进加权）** | 高 / 中 / 低 / 未知 | EXCEPTION_RISK（后果证据）、PAIN_POINT 中"漏/错"表述 |

**技术路线分岔规则**：文件化规则+数据全 → 规则引擎/RPA；口头/直觉规则+语料在 → LLM 主场（老师傅脑子里的规矩=待学习语料）；半结构化 → AI 提取/预填+人决策。

**分级表**：

| 级 | 信号组合（ROI 门槛后） | 技术路线 | 人审要求 |
|----|----------------------|---------|---------|
| A 直接自动化 | 规则文件化+数据全 | 规则引擎/RPA | 容错高=无｜中=抽样｜低/未知=强制 |
| B LLM 辅助 | 规则口头/直觉+语料在 | LLM 草稿 | 同上 |
| C 人机协作 | 半结构化 | AI 提取/预填 | 人决策在环内；容错低/未知=追加事前审批 |
| D 暂缓 | ROI 门槛筛除/无规则无数据/合规红线/伪需求嫌疑 | 数据治理/暂不投入 | — |

**处置层映射**（原方案三分类保留为展示层）：A → 优先执行节点；B/C → 辅助决策节点；D → 储备节点（进数据治理清单，暂缓）。

## 5. 输出规范

「三层输出」= ①分级(A/B/C/D) ②处置分类(优先执行/辅助决策/储备) ③技术路线+人审——承载于第 4 项（评估表三列）与第 5 项（分组方案）。

文件命名：`AI切入节点方案-{客户名或来源标识}-{YYYYMMDD}.md`，输出到当前工作区（用户指定目录时从其指定）。

固定结构（8 项，编号连续）：

1. **输入概况与模式声明**：逐字稿（全信号）/ 纪要（降档）；背景信息登记表（四项，缺失标"未提供"）；上游检测结果（无/已对齐，对齐时声明优先级）
2. **信号命中统计**：8 类标签 × 命中数 + 每类 1 条代表性原文引用
3. **动作链视图**：mermaid flowchart（按业务环节聚类着色，人工密集节点加粗）
4. **节点评估表**（10 列）：DIG-N{序}｜节点（业务动作）+流程环节｜命中信号（标签[+通道]）｜四维加权(频/耗/规/数，压缩式如"高/高/口头/部分")｜ROI（年人时或高/中/低）｜容错度｜分级+技术路线｜人审要求｜处置分类（优先执行/辅助决策/储备）｜纪要依据+缺口（关键≤3 条）
5. **A/B/C/D 分组方案**：各节点建议方案形态一句话（技术路线+人审+切入形态）；ROI 偏低节点标注"需客户明确意向"；愿望型节点附成本提示（"一键"背后常是多系统打通）
6. **待澄清清单**：UNCLEAR_REF / UNKNOWN_SPEAKER / 未提及字段 / 待验证愿望 / 矛盾信号 / NOTE-CHECK 标签清单导入行（A/全量 B/B*，v1.1.3），每条带原文位置
7. **人工评审表**：DIG-N｜节点｜分级｜状态（`待确认/已确认/已否决`）｜备注——产品经理评审入口
8. **尾注**：方法版本（AI-DIG 信号体系 v1.1 + ai-node 定级顺序 v1.2.2 对齐）、模式声明、分级为初判（终判留给客户确认）、与 Analysis 产出四关系声明（对齐模式必含）

## 6. 边界与纪律（硬规则）

1. **原文引用不可缺失**：任何节点输出必须附逐字稿/纪要原文和段落位置，无引用不予输出
2. **禁止脑补动作**：所有动作从受访者话语提取；可能发生但未提及的动作只能进待澄清，不进候选清单
3. **事实与推测显式区分**：`[推断]` 标注与原文依据视觉区分；无数字估分必标 `[推断]`
4. **分级为初判不下终判**：A/B/C/D 与方案形态是分析建议，终判留给客户
5. **容错度未知或低 → 方案必须含人审环节**
6. **说话人分不出标 UNKNOWN_SPEAKER，不猜**；该段信号置信降档
7. **纪要模式全节点置信度降一档**，尾注声明
8. **单份纪要单次运行**：文档修订后重跑，不增量合并；多轮沟通各产一份，文件名日期区分
9. **临时文件走系统 TEMP 目录**，不写 BaiduSyncdisk 工作区（同步锁坑）
10. **状态标记是人工评审接口，v1 不做自动学习闭环**（"反馈到节点库持续优化"无持久化机制支撑，降级为评审表输出）

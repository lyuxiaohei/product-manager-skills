# 软著申请表"主要功能和技术特点"生成提示词

> 本提示词已验证可用,直接使用,尽量不要修改。输入:操作手册内容 + 一份参考样例申请表。输出:纯文本"主要功能和技术特点",包裹在 ```txt 代码块。

---

# 任务目标
根据给定的软件操作手册（或功能说明文档）内容，按照指定软著申请表中"主要功能和技术特点"栏目的格式与风格，编写该软件对应软著申请表中的"主要功能和技术特点"部分。

# 输入要求
1. 您需要提供一份软件功能说明文档（如操作手册、产品说明书等），内容应覆盖该软件的全部核心功能模块。
2. 您需要提供一份目标软著申请表模板（或指明所需输出格式的参考样例），以便我严格遵循其结构、措辞风格和技术特点勾选方式。

# 字数限制
- 软件的主要功能 部分：总字数不超过700字（含标点，不含小标题本身及编号，仅统计各功能描述正文）
- 详细的软件的技术特点 部分：不超过100字符（含标点）
上述字数上限参照本次会话中提供的"一兆链采平台商品智能发布与审核系统"和"一兆链采平台多角色权限管控系统"软著样例确定，保持简洁风格。

# 输出格式与结构
请严格按照以下结构输出，不得遗漏或更改顺序。注意：由于输出为txt纯文本，所有层级通过换行与缩进体现，不使用Markdown加粗语法。

主要功能和技术特点

开发目的：[一句话概括该软件的建设目标，文案需简洁]

面向领域 / 行业：[如电商行业、金融行业等]

软件的主要功能：[总体介绍，然后以编号列表形式分功能模块描述，每个功能点以"X. 功能模块名称"为小标题。小标题与具体功能描述之间必须换行（即小标题写完后换一行再写描述内容）。各功能条目之间（即上一条目的描述内容结束后，换行直接写下一条目的小标题）不空行，保持紧凑排列]

软件的技术特点：[按软著表格式勾选适用的技术分类，例如：◻APP ◻游戏软件 ◻教育软件 ... 🗹云计算软件等，必须与软件实际技术特征匹配]

详细的软件的技术特点：[一段连贯、精炼的技术描述，涵盖架构、框架、算法、安全、性能、集成等，需与勾选的分类呼应，避免赘述]

# 格式示例
以下为"软件的主要功能"部分格式示例，说明换行与空行规则：

软件的主要功能：提供以下核心功能模块。具体功能描述如下：
1. 功能模块A
（此处为换行，小标题与描述之间必须换行）
该模块实现……功能，支持……操作。
（此处为换行，前一条目描述结束）
2. 功能模块B
（此处为换行，小标题与描述之间必须换行）
该模块实现……功能，支持……操作。
（此处为换行，前一条目描述结束）
3. 功能模块C
（此处为换行，小标题与描述之间必须换行）
该模块实现……功能，支持……操作。

注意：上述示例中，"1. 功能模块A"与描述之间有一行空行（换行），但"功能模块A的描述"与"2. 功能模块B"之间没有多余空行，仅有一个换行分隔。同理"2. 功能模块B"与"3. 功能模块C"之间也是如此。整个软件的主要功能各部分紧凑排列，仅在需要换行的地方换行。

# 格式与风格要求
- 措辞应正式、专业，符合软著申报的官方语言风格。
- 功能描述应具体、可操作，文案简洁精炼，在保证功能要点完整覆盖的前提下尽可能压缩字数，去除不必要的修饰性词语。
- 技术特点应体现软件的核心技术亮点，使用行业通用术语，简明扼要。
- 所有编号、符号（如🗹、◻）应严格参照参考样例。
- 全部内容使用纯文本格式，不加任何Markdown或HTML格式标记。
- 软件的主要功能中，每个功能小标题与其描述文本之间必须换行（即小标题后空一行再写描述）；各功能条目之间（描述结束到下一个小标题之间）不空行，仅用一个换行分隔。

- 若勾选的"技术特点"分类需要调整，请根据文档实际功能重新勾选，并同步修改详细技术描述，确保前后一致且内容紧凑。
- 最终输出时，请将全部内容包裹在 ```txt 代码块中，便于直接复制使用。

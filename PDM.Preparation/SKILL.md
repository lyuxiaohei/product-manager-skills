# PDM.Preparation · 产品经理预调研 — 数字化系统售前情报与调研指导引擎（v1.5.1）

> 输入「公司名 + 业务领域」，输出**售前情报三件套**：竞品功能对比矩阵（Excel，含功能页面列）、调研报告（HTML，正文=公司画像+竞品矩阵+问题清单，其余入附录）、会后更新闭环。目的：售前交流/需求调研之前完成准备，调研现场有指导，调研之后能收口到原型设计。

## 1. 定位与适用场景

回答一个核心问题：**"见这家客户之前，我需要知道什么、问什么、验证什么？"**

适用：
* 目标公司是潜在数字化客户，去售前交流 / 需求调研 / 原型设计前的准备
* 供应链物流领域为主战场（仓库管理 WMS / 运输管理 TMS / 订单管理 OMS / 报关 / 厂内物流等），框架层支持任意业务领域泛化
* 调研后需要把现场信息收口成原型设计输入（MoSCoW + 页面/字段/接口/POC）

不做：
* 报价测算、合同起草（商务动作，不在本技能）
* 替代实地调研（本技能产出的假设**必须**现场验证）
* 编造客户事实（公开信息查不到的字段必须问用户）
* 陌生客户破冰、大客户多角色决策链场景（v1.2 起无对抗话术/SPIN卡/首电编排，专为准入中小企业熟客场景设计）

## 2. 输入约定

| 参数 | 必需 | 说明 |
|------|------|------|
| 公司名 | ✅ | 目标客户公司名（可补充：已知的行业/规模信息；**复跑模式可省，从上次报告读取**） |
| 业务领域 | ✅ | 如：仓库管理（WMS）、运输管理（TMS）、订单管理（OMS）、报关、厂内物流……（**复跑模式可省，从上次报告读取**） |
| 已知客户信息 | 可选 | 用户已掌握的背景，有则填，减少检索轮次 |
| 现场记录 | 复跑模式 | 会后闭环模式输入：上次报告路径 + 现场调研记录（公司名/业务领域从报告自动读取，无需重填） |

运行中信息缺口 → 用 AskUserQuestion 向用户补充后再继续，**禁止编造**。

扫描版 pdf 类输入（招投标/年报等检索材料）先经 OCR 提文本再进流程（vinfield-PDF 方案；目标机无该技能时跳过扫描件源并声明，不阻塞纯文本检索）。

## 3. 执行流程（五阶段）

```
输入（公司名+业务领域）
  │
  ├─ ①公司画像 ──公开检索──→ 画像卡（档位/成熟度/存量系统/需求信号/时机信号）
  │      │缺口→问用户
  │      ▼
  ├─ ②竞品矩阵 ──检索+动态分层──→ Excel（打勾+星级+来源+客群/收费/价格带）
  │      ▼
  ├─ ③机会评估 ──画像×矩阵空白──→ 机会点转译为验证问题（并入问卷）
  │      ▼
  ├─ ④问题清单 ──框架×领域模板──→ 主线化问题流（物/钱/决策）+ 机会点验证问题
  │      ▼
  ├─ ⑤假设库+现场指导 ──三通道假设──→ 会前摘要/假设状态机
  │      ▼
  输出：HTML报告 + Excel矩阵
  （会后复跑：+现场记录 → 假设更新 → MoSCoW + 原型输入）
```

### 阶段① 公司画像（公开信息推断）

按优先级检索：
1. **官网/公开资料**：业务范围、仓储/网点规模、业务模式（自营/三方/多客户计费）
2. **招聘信息**：招 IT/数字化/信息化岗 = 需求信号；JD 提到 WMS/TMS/ERP = 存量系统线索
3. **招投标/采购公告**：采购过什么系统 = 判断存量替换 or 全新建设
4. **新闻/融资/工商**：扩张、扩仓、换届、融资 = 时机信号
5. **行业地位**：大/中/小企业档位判定（决定阶段②竞品分层）

产出画像卡五要素：**规模档位 / 数字化成熟度预判（高中低）/ 存量系统线索 / 需求信号 / 时机信号**。每条结论标注来源（官网/招聘/招标/新闻/用户口述）。

### 阶段② 竞品功能矩阵（动态分层）

**动态分层规则**（依据阶段①档位）：

| 客户档位 | 主对比层 | 参照行 |
|----------|----------|--------|
| 大型企业 | 国际主流 + 国内头部并列 | — |
| 中型企业 | 国内头部 SaaS | 国际巨头 + 轻量工具各 1-2 行（标注"非同类"） |
| 小微企业 | 轻量 SaaS 为主 | 国内头部 1-2 行 |

**矩阵结构**：
- 行 = 功能项（按领域功能框架展开，如 WMS：入库/上架/拣选/复核/发货/退货/盘点/批次效期/序列号/多仓/波次/越库/计费/报表/API…）
- 功能框架含 **AI/智能化能力分组**（领域自适应，通用种子行）：单据 OCR 识别 / 智能补货或调度建议 / 异常预警 / 辅助定价报价 / 报表自然语言问答 / 客服问答。竞品有无这些能力按公开信息（官网/发布会/版本日志）打勾，查不到标「待查证」——与 AI 机会透镜（阶段④）形成"行业有什么 × 客户哪里人工累"的交叉
- 每个竞品列 = ✅有 / ❌无 / ⚠️部分 + 星级（★~★★★★★）
- **评分锚点**（星级必须给依据）：功能完整度 / 易用性 / 集成能力（API/ERP对接）/ 性价比
- 每个数据点标注来源与可信度：`官方资料` / `第三方评测` / `推断（需验证）`
- 附加信息列：目标客群、收费模式（SaaS/私有部署/买断）、价格带、行业口碑简评、"好在哪"一句话
- **功能-菜单总表**（报告正文主交付，v1.7 起收敛原「对应功能页面列」+「竞品公司信息卡」两个分散设计）：功能概述→菜单路径（模块>菜单+一句话说明）1:N 行组 × 每竞品一列三态徽章（有据/待查证/无，标记体系见 `references/report-assets.md`），兼作原型页面骨架底稿＋竞品证据地图；公开信息查不到的菜单标「待查证」，禁止编造
- 表头标注检索日期（竞品信息有时效性）

**Excel 生成规范**：用 Python + openpyxl 生成（解释器取当前会话可用 Python，如 `python`/`py -3`；**禁止硬编码本机绝对路径**——分发包到他机必断，managed venv 场景由宿主环境注入）；文件命名 `竞品矩阵-{领域}-{YYYYMMDD}.xlsx`；同领域已有矩阵时**只增不删**（新竞品加列、新功能加行，历史数据保留），并在表头注明最近更新日期；历史文件增补「对应功能页面」列时同样只增不删，旧数据保留。

### 阶段③ 机会评估（并入画像卡与问卷，不单独成章）

1. **数字化成熟度预判**：依据画像信号（招聘/招标/存量系统）给出高/中/低 + 判断依据 → 已含在阶段①画像卡五要素内，不重复输出
2. **切入机会点** = 竞品矩阵空白（功能空白/档位空白/行业空白）× 该公司特点，列 2~4 个 → **全部转译为「机会点验证问题」**（形如「{空白场景}现在是怎么处理的？」），排在问题清单主线 3 之后、顺手要东西之前，现场验证机会真实性；报告正文不设机会评估章节。竞品空白扫描**含 AI 功能分组**：AI 空白 × 公司人工密集特征（画像/主线信号）= **AI 类机会点**，转译的机会点验证问题形如「{XX 智能场景}现在是怎么处理的？同行有做的吗？」

### 阶段④ 问题清单（主线化问题流 × 不设对象）

**主线识别规则**（领域可泛化）：每个业务领域抓住 2~3 个核心业务对象/流——

- **主线 1 · 核心物/作业流**：领域最核心的"物"（WMS=货、包装租赁=载具、TMS=车/运单）
- **主线 2 · 钱**：报价 → 结算 → 回款
- **主线 3 · 决策与扩张**：为什么现在、谁拍板、做多大

**每条主线内部追问链**——四步递进，**后一问由前一问的答案自然引出**：

```
现状（怎么记的）→ 痛点（丢没丢/痛在哪）→ 量化（丢多少/多痛，把形容词变数字）→ 收口（最想先解决什么）
```

**主线顺序**：主线 1 先问（最痛、最能打开话匣子）→ 主线 2 聊钱 → 主线 3 收口定范围 → 最后**"顺手要东西"**（实物采集，喂给第一版原型）：台账列头 → 单据样张 → 计费条款原文 → 异常收费标准 → 仓/客户/型号清单 → 实物标签照片。

**标注规则**：不设提问对象（中小企业现场谁在场问谁：老板/客服岗/财务/仓管）；优先级只分**「必问 / 选问」**两档。

**清单防锚定三闸**（客户提供需求清单时强制，防三种失效：名词未展开 / 证据未传导 / 问得浅）：
1. **术语展开**：客户清单里每个名词（仓型/物料形态/单据/系统名）必须展开五问链——物理形态→时效规则→计量方式→追溯粒度→作业动线；一个名词背后常压着一整层行业深度
2. **证据承接闸门**：进入竞品矩阵或行业检索的每个术语（如批次效期/复验期/序列号/货主）必须有至少一个问题编号承接，否则阶段②④未完成
3. **档位由影响定**：领域内高影响 × 客户未提及 → 必问；客户已明写 → 验证性一问即可——深水区不因客户没提而挂选问，也不因客户提了而反复深挖
现场纪律配套：先对照验证清单（建信任拿数字），清单外行业问题收口后以「同行普遍做法」话术后置；补必问须做时间预算（必问膨胀＝必问失效）。

**AI 机会透镜（四漏斗+容错度，挂载式追问）**——识别可由智能体/大模型承接的节点：

- **不设独立 AI 主线**，挂在现有主线的"人工密集"动作节点上：主线 1 的"哪几步靠人记/人盯"、主线 2 的"对账/异常判定"
- 每个挂载点 **4+1 问**：重复（这一步一天/一月多少次）→ 耗时（每次几分钟/几人时）→ 规则（有章可循？写在文件里还是装在谁脑子里）→ 数据（做这事的单据/记录/语料在哪）→ 容错度（做错了最贵一次多少）
- **顺序纪律**：先问值不值（重复×耗时=ROI）→ 再问能不能（规则×数据=技术路线）→ 最后校容错度（定人审与否）
- **规则分岔**：规则明确→规则引擎/RPA；规则模糊但有语料→LLM 辅助（草稿生成/信息提取/分类打标）
- **标注**：默认【选问】；节点命中"高频+耗时"信号时升级必问；单场控制在主线问题量 1/4 以内
- 方法细节与 A/B/C/D 分级表见 `references/funnel-framework.md` 第八章

**领域泛化三层结构**：
```
框架层（固定）：主线化问题流（物/钱/决策三主线 × 现状→痛点→量化→收口）× MoSCoW × AI 机会透镜 —— 全领域通用（references/funnel-framework.md）
模板层（积累）：常见领域内置种子模板。首颗种子：WMS（references/wms-questions.md）
生成层（兜底）：无模板领域 → 按框架层现场生成 + 检索补领域知识，并提示用户可回填为新模板
```

### 阶段⑤ 假设库 + 调研现场指导

**假设库**（3~5 条，三通道来源）：

| 假设类型 | 来源 | 示例 |
|----------|------|------|
| 行业痛点假设 | 领域通用痛点 × 客户特征 | 库存准确率低于 95% |
| 竞品短板映射 | 画像存量系统 → 矩阵短板列 | 在用竞品A → 波次策略僵化 |
| 时机假设 | 公开信号（扩仓/融资/换届/招标） | 明年扩仓 → 此时切入绑定整体方案 |

- **单向链接**（内部用，问题里不标编号）：假设内部标注"由主线N第N问验证"；问题清单本身不出现"验证假设N"标签，保持对话流自然
- **状态机**：`待验证` → 现场回答喂回后更新 → `已验证` / `证伪` / `部分验证` / `未覆盖`（纪要未触及）；旧报告"已否定"读作"证伪"

**调研现场指导**：
- **会前**：客户背景摘要 + 痛点假设（带假设去验证，非纯记录）
- **会中**：量化追问内核已融入主线追问链（把形容词变数字），不再单设话术卡
- **会后**：假设状态更新 → MoSCoW 确认单（必须做/应该做/暂不做）→ 原型设计输入清单

## 4. 会后轻量回写（复跑模式）

> 会后转化（MoSCoW/原型输入/需求审核）**统一走 PDM.Preparation-Analysis**，本技能只做报告侧轻量回写，不重复产出转化类交付物。

触发：用户提供「上次报告路径 + 现场调研记录」（公司名/领域从报告读取）。

流程：
1. 解析现场记录，逐条映射到假设 → 四态更新（已验证/证伪/部分验证/未覆盖），回写报告假设库
2. 差异视图：哪些验证了、哪些证伪、新发现什么（含 **AI 信号段落索引**——仅标纪要中 AI 相关段落位置，不做分级判断，分级统一由 PDM.Preparation-Analysis 产出四执行）
3. 画像刷新：档位/成熟度/时机信号有新证据时更新画像卡
4. 沉淀：新发现的好问题/领域知识 → 提示用户回填领域模板
（MoSCoW 确认单、原型设计输入、AI 潜在节点方案 → 见 PDM.Preparation-Analysis 四件产出）

## 5. 输出规范

**HTML 报告**（骨架见 `references/report-template.html`）结构 = 正文三件套 + 附录：

正文（初步版保持简洁，聚焦公司情况与竞品分析）：
1. 公司画像卡（含数字化成熟度预判）
2. 竞品矩阵摘要：**单张「功能-菜单总表」**——第一列功能概述（rowspan 1:N 行组）、第二列菜单路径（模块>菜单）+一句话说明、第三列客户需求关联、其后**每个竞品一列三态徽章**（有多少竞品多少列；✓公开可证 / ?待查证 / —明确无，标记资产见 `references/report-assets.md`，**禁止 emoji 与普通字符混排**）；表尾注明"兼作原型页面骨架底稿（一二级菜单树直接取用）+ 竞品证据地图（?格=现场演示验证清单）"；竞品公司信息卡降级为表下来源附注或附录；星级/评分完整对比在 Excel

## 6. 边界与纪律（硬规则）

1. 公开信息查不到的字段必须问用户，**禁止编造**公司事实
2. 星级评分必须标注来源与可信度；推断的必须标"推断（需验证）"
3. 竞品信息标注检索日期
4. Excel 竞品矩阵同领域复用时**只增不删**
5. 不做：报价测算、合同起草、替代实地调研
6. 临时文件（检索中间产物）写系统临时目录，不写 BaiduSyncdisk 工作区（同步锁坑）
7. 功能页面/竞品菜单结构查不到的标「待查证」，禁止编造（防幻觉核心约束）
8. 历史文件增补「对应功能页面」列/AI 能力分组行时只增不删，旧数据保留
9. 表格状态标记必须单一渲染机制（单一字符集或单一 CSS 类，风格一致性由生成机制保证），禁止 emoji（✅）与普通字符混排——跨平台渲染不一致即"不专业"观感的来源；标记资产见 `references/report-assets.md`
